Yo'l xaritasi / Android: suhbatga tayyorgarlik

A1. Kotlin va Java: farqlar, turlar, null xavfsizligi

Savol: Kotlin Java'dan nimasi bilan farq qiladi, nega u Android'ning asosiy tiliga aylandi, va ichkarida uning turlari qanday ishlaydi?

Bu nima

Kotlin JetBrains kompaniyasi yaratgan til. U ham Java kabi JVM baytkodiga kompilyatsiya qilinadi (P0 ning 7-darsi), shuning uchun Java bilan bitta loyihada yonma-yon ishlaydi va Java kutubxonalarini to'g'ridan-to'g'ri chaqiradi.

Kotlin Java'ning eng og'riqli joylarini til darajasida yopadi: null xatolari, ortiqcha kod, va o'zgaruvchanlik nazorati.

Qayerda ishlatiladi

  • Android'da asosiy til: Google 2019-yildan «Kotlin birinchi» yondashuvini e'lon qilgan. Jetpack Compose faqat Kotlin'da.
  • Backend'da: Spring Kotlin'ni to'liq qo'llaydi, Ktor esa Kotlin uchun yozilgan server freymvorki.
  • Suhbatda: «Kotlin va Java farqi», «Int va Int? farqi», «data class nima yaratadi» deyarli har bir Android suhbatining birinchi savollari.

Bu darsning maqsadi

Darsdan keyin siz quyidagilarni tushuntira olasiz:

  • Kotlin kodi telefonga yetib borguncha qanday yo'l bosadi;
  • Int, Int? va List<Int> xotirada qanday saqlanadi va == bilan === farqi;
  • null xavfsizligi qanday ishlaydi va qayerda u buziladi;
  • data class, object, sealed, kengaytma funksiya ichkarida nimaga aylanadi;
  • lateinit va by lazy, Any, Unit, Nothing.

Pastdagi chizmada Android ilovaning qavatlari. Bu bo'limning har bir darsi shu qavatlardan biri haqida. Bu dars eng pastki qavat haqida: qolgan hamma narsa yoziladigan til.

Bu dars qamraydi

  • Kotlin qaysi og'riqdan paydo bo'lgan
  • Kompilyatsiya yo'li: Kotlin, baytkod, DEX, ART
  • Turlar: primitiv va «qutilangan» son, == va ===
  • Null xavfsizligi va platforma turlari
  • val va var, const, lateinit, by lazy
  • data class, object, companion object, sealed, enum, kengaytma funksiyalar
  • Any, Unit, Nothing

Bu darsga kirmaydi

  • Lambda, inline, crossinline, reified, scope funksiyalar: A2-darsda
  • Coroutines: A3-darsda

1. Og'riqAndroid'da Java bilan yashash

Android 2008-yilda Java tili bilan chiqdi. Uch muammo yillar davomida to'planib bordi.

  • NullPointerException. Java'da har qanday havola null bo'lishi mumkin, va kompilyator buni tekshirmaydi. Ilova foydalanuvchi qo'lida ishlab turganda qulaydi. null ning muallifi Toni Xoar 2009-yilda uni o'zining «milliard dollarlik xatosi» deb atagan: 1965-yilda kiritilgan bu qulaylik o'n yillar davomida son-sanoqsiz nosozlikka sabab bo'lgan. Android ilovalardagi qulashlarning eng ko'p uchraydigan sababi aynan shu edi.
  • Ortiqcha kod. Ikki maydonli oddiy ma'lumot klassi uchun Java'da konstruktor, getterlar, equals, hashCode, toString qo'lda yoziladi: o'nlab qator. Maydon qo'shilsa, ularning hammasini yangilash kerak, unutilsa, xato.
  • Eski Java. Android uzoq vaqt Java 6 va 7 imkoniyatlari bilan qolib ketdi: lambda yo'q, oqimlar yo'q. Java 8 ning lambdalari Android'ga to'liq yetib kelishi uchun yillar kerak bo'ldi.

Kerak bo'lgan narsa: Java bilan to'liq mos, uning kutubxonalarini ishlatadigan, lekin bu og'riqlarni til darajasida yopadigan til. JetBrains aynan shunday tilni o'z mahsulotlari uchun yaratdi.

2. IchkaridaKotlin qanday ishlaydi

Kodingizdan telefongacha

Kotlin kompilyatori .kt faylni Java kompilyatori kabi JVM baytkodiga aylantiradi. Lekin telefonda JVM yo'q: Android'ning o'z runtime'i bor, u ART deyiladi va o'z baytkodini, DEX ni tushunadi. Shuning uchun yig'ish jarayonida yana bir qadam bor: D8 (yoki kod kichraytiruvchi R8) barcha .class fayllarni bitta yoki bir nechta classes.dex faylga aylantiradi. Telefonda esa ART DEX ni protsessor uchun mashina kodiga aylantiradi: bir qismini o'rnatishda oldindan, bir qismini ish paytida JIT bilan.

Bundan ikki xulosa. Birinchisi: Kotlin va Java bitta baytkodga tushgani uchun ular bir-birini to'g'ridan-to'g'ri chaqiradi, hech qanday ko'prik kerak emas. Ikkinchisi: Kotlin'ning ko'p «sehri» aslida kompilyatorning ishi. data class yozsangiz, kompilyator siz uchun Java'da qo'lda yoziladigan metodlarni yaratadi. Darsning qolgan qismi asosan shu: Kotlin yozuvi ichkarida nimaga aylanadi.

Turlar: Kotlin'da primitiv yo'q, baytkodda bor

Java'da ikki xil tur bor: primitivlar (int, long, boolean) va obyektlar (Integer, Long, String). Primitiv bu 4 yoki 8 baytli sonning o'zi. Obyekt esa xotiraning boshqa joyidagi alohida bo'lak (heap), o'zgaruvchida faqat unga havola turadi. Har bir Integer obyekti 4 baytli son uchun 16 bayt atrofida joy oladi: obyekt sarlavhasi va qiymat.

Kotlin'da dasturchi faqat bitta Int ni ko'radi. Qaysi biriga aylanishini kompilyator hal qiladi:

  • Int (null bo'lmaydigan) iloji boricha primitiv int bo'ladi;
  • Int? (null bo'lishi mumkin) obyekt Integer bo'ladi, chunki primitivda «hech narsa» degan qiymat yo'q;
  • List<Int> ichidagi sonlar ham Integer, chunki JVM generiklari faqat obyektlar bilan ishlaydi. Primitivlar massivi kerak bo'lsa, IntArray ishlatiladi.

Sonni obyektga o'rash qutilash (boxing) deyiladi. Uning bitta tuzog'i bor, va u suhbatlarda ko'p so'raladi: JVM −128 dan 127 gacha bo'lgan Integer obyektlarini oldindan yaratib, keshda saqlaydi. Shu oraliqdagi son qutilansa, yangi obyekt yaratilmaydi, keshdagisi beriladi. Pastdagi chizmada son va e'lonni tanlang.

Asosiy qoida: == qiymatni solishtiradi (ichkarida equals chaqiriladi), === havolani solishtiradi, ya'ni ikki o'zgaruvchi aynan bitta obyektni ko'rsatadimi. Java'da esa == obyektlar uchun havolani solishtiradi, va Integer a = 1000, b = 1000; a == b yolg'on chiqadi. Bu Java'dagi eng mashhur tuzoqlardan biri, Kotlin'da u == ning ma'nosini o'zgartirish bilan yopilgan.

Null xavfsizligi

Kotlin'da tur ikki xil bo'ladi: String hech qachon null bo'lmaydi, String? null bo'lishi mumkin. Kompilyator String? qiymatda to'g'ridan-to'g'ri metod chaqirishga ruxsat bermaydi: avval null emasligini tekshirish kerak. Shu bilan NullPointerException ning katta qismi ish paytidan kompilyatsiya paytiga ko'chadi: xato foydalanuvchida emas, dasturchining ekranida chiqadi.

Null bo'lishi mumkin qiymat bilan ishlash uchun to'rtta vosita bor:

  • ?. xavfsiz chaqiruv: qiymat null bo'lsa, butun ifoda null qaytaradi va davom etmaydi;
  • ?: Elvis operatori: chap tomon null bo'lsa, o'ng tomonni oladi;
  • !! «ishonaman, null emas»: null bo'lsa, NullPointerException tashlaydi;
  • aqlli tur o'zgarishi (smart cast): if (x != null) dan keyin kompilyator x ni null emas deb biladi.

Null xavfsizligining bitta teshigi bor: platforma turlari. Java kodidan kelgan qiymat haqida Kotlin null bo'lish-bo'lmasligini bilmaydi, chunki Java'da bu ma'lumot yo'q. Bunday tur xato xabarlarida String! deb ko'rsatiladi va kompilyator uni tekshirmaydi. Java kutubxonasi kutilmaganda null qaytarsa, Kotlin kodi ham qulaydi. Himoya: Java'dan kelgan qiymatni darhol aniq tur bilan e'lon qilish (val nom: String? = javaObyekt.getName()), va Java kodida @Nullable, @NonNull annotatsiyalaridan foydalanish: Kotlin ularni o'qiydi.

val, var va o'zgarmaslik

val qayta tayinlab bo'lmaydigan o'zgaruvchi (Java'dagi final), var esa oddiy o'zgaruvchi. Muhim nozik joy: val havolani qotiradi, obyektni emas. val ro'yxat = mutableListOf(1, 2) ga baribir element qo'shish mumkin. Kotlin'da kolleksiyalar ikki xil interfeysga ega: List (faqat o'qish) va MutableList (o'zgartirish). Ekran holatini List bilan e'lon qilish uni tasodifan o'zgartirishdan himoya qiladi.

  • const val: kompilyatsiya paytida ma'lum bo'lgan oddiy qiymat (son, satr). Ishlatilgan joyga to'g'ridan-to'g'ri qo'yib yuboriladi. Faqat yuqori darajada yoki object ichida.
  • lateinit var: qiymat keyinroq beriladi (masalan, testda yoki DI orqali). Faqat var, faqat null bo'lmaydigan va primitiv bo'lmagan tur. Berilmasdan o'qilsa, UninitializedPropertyAccessException. Tekshirish: ::x.isInitialized.
  • val x by lazy { ... }: qiymat birinchi murojaatda bir marta hisoblanadi va saqlanadi. Sukut bo'yicha oqimlar uchun xavfsiz (sinxronlashtirilgan). Faqat val.

Kompilyator siz uchun yozadigan kod

Kotlin'ning bir nechta kalit so'zi kompilyatorga «bu klass uchun standart kodni o'zing yoz» deydi. Pastdagi chizmada bitta qator Kotlin kodi baytkodda nimaga aylanishi ko'rsatilgan.

sealed va enum farqi. Ikkalasi ham «cheklangan variantlar to'plami». enum ning har bir qiymati bitta tayyor obyekt va hammasi bir xil maydonlarga ega. sealed class yoki sealed interface ning har bir varianti alohida klass: har xil maydonlarga ega bo'ladi va istalgancha nusxasi yaratiladi. Masalan ekran holati: Yuklanmoqda (maydonsiz), Tayyor(kartalar), Xato(xabar). Ikkalasida ham when barcha variantlarni tekshirishga majbur qiladi: yangi variant qo'shilsa, ko'rib chiqilmagan joylar kompilyatsiya xatosi beradi.

Any, Unit, Nothing. Any barcha null bo'lmaydigan turlarning otasi (Java'dagi Object). Unit «hech narsa qaytarmaydi» degani (Java'dagi void), lekin u haqiqiy tur va yagona qiymatga ega, shuning uchun uni generiklarda ishlatish mumkin. Nothing hech qachon qiymat qaytarmaydigan ifodaning turi: throw, TODO(), cheksiz sikl. U barcha turlarning «bolasi», shuning uchun val x: String = y ?: throw ... kompilyatsiya bo'ladi.

4. Atamalar

ART
Android Runtime: telefonda ilovani bajaradigan muhit. DEX baytkodini o'rnatishda oldindan va ish paytida mashina kodiga aylantiradi.
DEX, D8, R8
DEX: Android baytkodi formati. D8: JVM baytkodini DEX ga aylantiradigan asbob. R8: D8 ning ustiga kodni kichraytirish, nomlarni chalkashtirish (obfuskatsiya) va optimallashtirishni qo'shadigan asbob.
Qutilash (boxing)
Primitiv sonni obyektga o'rash: int dan Integer. Kotlin'da Int? va generiklarda avtomatik bo'ladi.
Integer keshi
JVM oldindan yaratib qo'yadigan −128 dan 127 gacha Integer obyektlari.
Strukturaviy va havola tengligi
==: qiymatlar teng (equals). ===: bitta obyekt.
Null xavfsizligi
Null bo'lishi mumkin va mumkin bo'lmagan turlarni ajratib, null tekshiruvini kompilyatorga yuklash.
Platforma turi
Java'dan kelgan, null bo'lish-bo'lmasligi noma'lum tur. String! deb ko'rsatiladi, kompilyator tekshirmaydi.
Aqlli tur o'zgarishi (smart cast)
Tekshiruvdan keyin kompilyatorning o'zgaruvchi turini o'zi aniqlashtirishi.
data class
Kompilyator equals, hashCode, toString, copy va componentN ni yaratib beradigan ma'lumot klassi.
object, companion object
object: yagona nusxali klass (singleton). companion object: klass ichidagi shunday obyekt, Java'dagi statik a'zolar o'rnida.
Kengaytma funksiya
Mavjud klassga uning kodini o'zgartirmasdan «qo'shilgan» funksiya. Ichkarida birinchi parametri o'sha obyekt bo'lgan statik metod.
sealed
Barcha vorislari bitta modulda va oldindan ma'lum bo'lgan klass yoki interfeys. when uni to'liq tekshira oladi.
Any, Unit, Nothing
Barcha turlarning otasi; «qiymat yo'q» degan yagona qiymatli tur; hech qachon qiymat qaytarmaydigan ifoda turi.

5. AmaliyotdaTuzoqlar

Tuzoq: !! null xavfsizligini o'chiradi

Kompilyator xato bersa, !! qo'yib qo'yish eng tez «yechim». Lekin bu Java'dagi holatga qaytish: null kelsa, ilova qulaydi. Bank ilovasida bu odatda serverdan kutilmagan javob kelganda sodir bo'ladi: maydon bo'sh keldi va ekran ochilmay qoldi.

To'g'risi: null holatini ataylab hal qilish. ?: bilan zaxira qiymat, ?: return bilan erta chiqish, yoki xatoni foydalanuvchiga tushunarli ko'rsatish. Kod ko'rib chiqishda har bir !! savol tug'dirishi kerak.

Tuzoq: data class ni HashSet yoki HashMap kaliti qilib, keyin o'zgartirish

hashCode asosiy konstruktordagi xususiyatlardan hisoblanadi. Obyekt HashSet ga qo'shilgandan keyin uning var xususiyati o'zgartirilsa, u endi to'plamda «topilmaydi»: u eski xesh bo'yicha joylashgan.

To'g'risi: data class xususiyatlarini val qilish va o'zgarish kerak bo'lsa copy() bilan yangi obyekt yaratish. MVI dagi ekran holati aynan shunday ishlaydi: holat o'zgarmaydi, har safar yangi nusxa.

Tuzoq: kengaytma funksiya polimorf emas

Kengaytma funksiya statik metod bo'lgani uchun qaysi biri chaqirilishi o'zgaruvchining e'lon qilingan turiga qarab kompilyatsiya paytida hal qilinadi, obyektning haqiqiy turiga qarab emas. Ota va bola klassga bir xil nomli kengaytma yozilsa va bola obyekt ota turidagi o'zgaruvchida tursa, otaniki chaqiriladi.

Shuningdek, klassning o'z a'zo funksiyasi bir xil nomli kengaytmadan doim ustun. Kengaytma klassning private qismlariga ham kira olmaydi.

Tuzoq: Java'dan kelgan qiymat

Retrofit, Gson kabi Java'da yozilgan yoki refleksiya bilan ishlaydigan kutubxonalar Kotlin'ning null bo'lmaydigan maydoniga null yozib qo'yishi mumkin. Masalan, Gson Kotlin konstruktorini chetlab o'tadi va serverdan kelmagan maydon String turida bo'lsa ham null bo'lib qoladi. Xato keyinroq, butunlay boshqa joyda chiqadi.

To'g'risi: serverdan keladigan modellarda ixtiyoriy maydonlarni String? deb e'lon qilish va Kotlin'ni tushunadigan kutubxonadan foydalanish: kotlinx.serialization yoki Moshi. Bu A9-darsda.

6. SuhbatdaSavol va namunaviy javoblar

Avval javobni o'zingiz ovoz chiqarib ayting, keyin oching. Namunaviy javob yod olish uchun emas: undagi asosiy fikrlar sizning javobingizda bo'lishi kerak.

Kotlin Java'dan nimasi bilan farq qiladi?

Ikkalasi ham JVM baytkodiga kompilyatsiya qilinadi va bir-biri bilan to'liq mos ishlaydi. Asosiy farqlar: Kotlin'da null xavfsizligi tur tizimida (String va String?), Java'da yo'q. Kotlin ixchamroq: data class, xususiyatlar, standart va nomlangan argumentlar, when, kengaytma funksiyalar. Kotlin'da tekshiriladigan istisnolar (checked exceptions) yo'q. Funksiyalar birinchi darajali qiymat: lambda va yuqori tartibli funksiyalar tilning asosi, inline bilan ularning narxi yo'qotiladi. Asinxronlik uchun coroutines. Primitiv va obyekt turlari dasturchidan yashirin, kompilyator tanlaydi. == qiymatni solishtiradi. Kolleksiyalar faqat o'qish va o'zgartirish interfeyslariga bo'lingan.

Int va Int? farqi nima? Xotirada qanday saqlanadi?

Int null bo'la olmaydi va kompilyator uni iloji boricha primitiv int qiladi: 4 bayt. Int? null bo'lishi mumkin, primitivda esa null yo'q, shuning uchun u java.lang.Integer obyektiga qutilanadi: heap'da taxminan 16 bayt va unga havola. Generiklarda ham (List<Int>) qutilanadi. Ko'p sonli ro'yxatda bu xotira va tezlikka ta'sir qiladi, primitiv massiv kerak bo'lsa IntArray.

== va === farqi nima? val a: Int? = 1000; val b: Int? = 1000; a === b nima beradi?

== qiymatni solishtiradi (equals, null xavfsiz), === havolani, ya'ni bitta obyektmi. 1000 qutilanganda har safar yangi Integer obyekti yaratiladi, shuning uchun a === b yolg'on, a == b rost. 100 bo'lsa, ikkalasi ham rost, chunki JVM −128 dan 127 gacha Integer obyektlarini keshdan beradi. Kotlin qutilangan sonlar uchun === ishlatilsa ogohlantirish beradi, chunki natija qiymatga bog'liq.

val, const val va var farqi? lateinit va by lazy farqi?

var o'zgaradi, val bir marta tayinlanadi (lekin u ko'rsatgan obyekt o'zgarishi mumkin), const val kompilyatsiya paytida ma'lum oddiy qiymat va u ishlatilgan joyga qo'yib yuboriladi. lateinit: faqat var, null bo'lmaydigan, primitiv bo'lmagan tur, qiymat keyin beriladi, berilmasdan o'qilsa istisno. by lazy: faqat val, birinchi murojaatda hisoblanadi, sukut bo'yicha sinxronlashtirilgan, keyin keshlanadi.

data class nima yaratadi va qanday cheklovlari bor?

Asosiy konstruktordagi xususiyatlar asosida equals, hashCode, toString, copy va component1, component2 va hokazo (destrukturlash uchun). Klass tanasidagi xususiyatlar bularga kirmaydi. Cheklovlar: asosiy konstruktorda kamida bitta parametr, data class abstract, open, sealed yoki inner bo'la olmaydi. Java 16 dagi record bunga o'xshaydi, lekin copy yo'q va maydonlari doim o'zgarmas.

object va companion object nima? Ular Java'da nimaga aylanadi?

object yagona nusxali klass: kompilyator statik INSTANCE maydonini yaratadi, u klass birinchi yuklanganda bir marta va oqimlar uchun xavfsiz yaratiladi. companion object klass ichidagi shunday obyekt, nomi sukut bo'yicha Companion. Java'dan Klass.Companion.metod() deb chaqiriladi; to'g'ridan-to'g'ri statik metod bo'lishi uchun @JvmStatic qo'yiladi.

sealed class va enum farqi? Qachon qaysi biri?

enum: qat'iy qiymatlar ro'yxati, har biri bitta obyekt, hammasining tuzilishi bir xil (masalan, karta turi: UZCARD, HUMO, VISA). sealed: cheklangan variantlar, lekin har biri o'z maydonlariga ega alohida klass va har biridan ko'p nusxa (masalan, ekran holati yoki tarmoq natijasi: Success(data), Error(code, message), Loading). Ikkalasi ham when da to'liq tekshiriladi.

Kengaytma funksiya ichkarida nima? Uni ota klassda va bola klassda bir xil nom bilan yozsak nima bo'ladi?

Ichkarida bu statik metod, birinchi parametri o'sha obyekt. Klassning o'zi o'zgarmaydi va kengaytma private qismlarga kira olmaydi. Qaysi kengaytma chaqirilishi o'zgaruvchining e'lon qilingan turiga qarab kompilyatsiya paytida hal qilinadi, shuning uchun polimorfizm yo'q. Klassning o'z a'zo funksiyasi doim ustun.

Platforma turi nima va qanday xavfli?

Java'dan kelgan, null bo'lish-bo'lmasligi noma'lum tur, String!. Kompilyator uni tekshirmaydi, shuning uchun Java metodi null qaytarsa va biz uni String deb ishlatsak, NullPointerException. Himoya: qiymatni aniq tur bilan qabul qilish va Java kodida @Nullable annotatsiyalari.

Any, Unit va Nothing nima?

Any: barcha null bo'lmaydigan turlarning ildizi (Object ga o'xshash, equals, hashCode, toString). Unit: qaytaradigan qiymati yo'q funksiyaning turi, yagona qiymatli haqiqiy obyekt, shuning uchun generiklarda ishlatiladi (() -> Unit). Nothing: qiymati yo'q tur, hech qachon normal qaytmaydigan ifodalar uchun (throw, TODO()); u har qanday turning o'rnida tura oladi.

7. Tekshiruv

Javoblarni chatga yozing, men suhbatdoshdek baholayman.

  1. Kotlin kodi telefonda ishga tushguncha qaysi bosqichlardan o'tadi?
  2. val x: Int? = 127; val y: Int? = 127. x === y nima beradi? 128 bo'lsa-chi? Nega?
  3. Server javobidagi maydon ba'zan kelmaydi. Kotlin modelida uni qanday e'lon qilasiz va ekranda qanday ko'rsatasiz?
  4. Ekran holati uchun nega sealed interface, karta turi uchun nega enum?
  5. DigitalBank'da qayerda Java va Kotlin aralash ishlatilgan edi, yoki ishlatilganmi? Bu qanday muammo tug'dirdi?

Chuqurroq

Generiklar: in, out va tur o'chirilishi

JVM da generik tur ma'lumoti ish paytida o'chiriladi: List<String> va List<Int> ish paytida bir xil List. Shuning uchun if (x is List<String>) yozib bo'lmaydi. Kotlin'da buning yechimi inline funksiyadagi reified tur, A2-darsda. Variantlik: out T faqat beradi (ishlab chiqaruvchi), shuning uchun List<String> ni List<Any> o'rnida ishlatish mumkin; in T faqat qabul qiladi (iste'molchi), masalan Comparator<in T>. Java'da bu ? extends va ? super.

value class nima?

@JvmInline value class KartaRaqami(val qiymat: String): kompilyatsiyada iloji boricha ichidagi qiymatning o'ziga aylanadigan klass. Natijada tur xavfsizligi bor (karta raqami o'rniga telefon raqamini berib bo'lmaydi), lekin qo'shimcha obyekt yaratilmaydi. Bank ilovasida summa, valyuta, identifikatorlar uchun foydali.
