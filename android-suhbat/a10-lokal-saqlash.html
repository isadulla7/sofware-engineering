A10. Lokal saqlash: Room va DataStore

Savol: ilova ma'lumotni qurilmada qayerda va qanday saqlaydi, baza o'zgarganda ekran o'zi qanday yangilanadi, sxema o'zgarganda foydalanuvchi ma'lumoti qanday saqlab qolinadi, va sozlamalar uchun nega SharedPreferences emas, DataStore?

Bu nima

Room: SQLite ustidagi Jetpack kutubxonasi. Jadvallar Kotlin klasslari, so'rovlar annotatsiyadagi SQL, va u kompilyatsiyada tekshiriladi. Natijani suspend yoki Flow bilan qaytaradi.

DataStore: kichik ma'lumot (sozlamalar, bayroqlar) uchun asinxron, tranzaksiyali, Flow asosidagi saqlash. SharedPreferences'ning o'rnini bosadi.

Qayerda ishlatiladi

  • Vakansiyada: «lokal bazalar va saqlash bilan ishlash tajribasi: Room va Jetpack DataStore».
  • Bank ilovasida: kartalar va operatsiyalar keshi (internet yo'q paytda ham ko'rsatish), sozlamalar (til, tema, balansni yashirish), qoralamalar.
  • Sizning tajribangiz: Oracle va PL/SQL: SQL, indekslar, tranzaksiyalar sizga tanish. Suhbatda buni Room'ga bog'lash kuchli tomoningiz.

Bu darsning maqsadi

1. Og'riqQo'lda SQL va bloklovchi sozlamalar

Android'da SQLite 2008-yildan bor, lekin u bilan ishlash qiyin edi. SQLiteOpenHelper, so'rovlar satr sifatida, natija Cursor orqali ustunlarni raqami bo'yicha o'qish. SQL dagi xato (ustun nomi, sintaksis) faqat ish paytida chiqardi. Har bir jadval uchun o'nlab qator mapping kodi. So'rov asosiy oqimda bajarilsa, ekran qotardi. Ma'lumot o'zgarganda ekranni yangilash qo'lda.

Sozlamalar uchun SharedPreferences ishlatilardi, va uning o'z og'riqlari bor: birinchi o'qishda butun faylni sinxron yuklaydi (asosiy oqimda bo'lsa, qotish), apply() fonda yozadi, lekin Activity to'xtaganda tizim bu yozuvlarni kutadi va bu ANR larga olib kelgan; tur xavfsizligi yo'q (kalit satr, tur o'qishda tanlanadi), xatolar istisno sifatida qaytmaydi, bir nechta qiymatni atom tarzda o'zgartirish yo'q.

Kerak bo'lgan narsa: SQL ni kompilyatsiyada tekshiradigan, asinxron, o'zgarishlarni o'zi xabar qiladigan baza; va sozlamalar uchun asinxron, xavfsiz, tranzaksiyali saqlash.

2. IchkaridaRoom va DataStore

Room: uchta qism

@Entity(tableName = "cards", indices = [Index("ownerId")])
data class CardEntity(@PrimaryKey val id: String, val ownerId: String, val masked: String, val balanceTiyin: Long)

@Dao
interface CardDao {
    @Query("SELECT * FROM cards WHERE ownerId = :owner ORDER BY masked")
    fun observe(owner: String): Flow<List<CardEntity>>          // o'zgarsa qayta chiqaradi
    @Upsert suspend fun upsertAll(cards: List<CardEntity>)
    @Query("DELETE FROM cards") suspend fun clear()
    @Transaction suspend fun replaceAll(cards: List<CardEntity>) { clear(); upsertAll(cards) }
}

@Database(entities = [CardEntity::class, TxEntity::class], version = 2, exportSchema = true)
@TypeConverters(Converters::class)
abstract class BankDb : RoomDatabase() { abstract fun cardDao(): CardDao }
  • Entity: jadval. Maydonlar ustunlar, @PrimaryKey, indekslar.
  • DAO: so'rovlar. @Query dagi SQL kompilyatsiyada (KSP) tekshiriladi: jadval yoki ustun nomi xato bo'lsa, ilova yig'ilmaydi. @Insert, @Update, @Delete, @Upsert SQL siz.
  • Database: jadvallar ro'yxati va versiya. Room KSP bilan barcha DAO larning amalga oshirilishini yaratadi.
  • TypeConverter: SQLite bilmaydigan turlarni saqlash: Instant ni Long ga, BigDecimal ni String ga (P0, 3-dars: pulni REAL ustunda saqlamang).
  • @Transaction: bir nechta amalni bitta tranzaksiyada: hammasi yoki hech biri. Oracle'dagi COMMIT/ROLLBACK bilan bir xil g'oya.

Flow: baza o'zgarganini Room qanday biladi

DAO metodi Flow qaytarsa, Room so'rovni bajarib natijani chiqaradi va keyin kutadi. Ichkarida InvalidationTracker SQLite triggerlari orqali qaysi jadvallar o'zgarganini kuzatadi. Bazaga yozuvchi tranzaksiya tugaganda, Room o'zgargan jadvallar ro'yxatini tekshiradi va shu jadvallarni o'qiydigan barcha Flow larga «qayta so'ra» deydi. Muhim nozik joy: kuzatuv jadval darajasida, qator darajasida emas. Pastda sinab ko'ring.

Bitta haqiqat manbai: avval baza, keyin tarmoq

Bank ilovasida ekran ma'lumotni qayerdan oladi: tarmoqdanmi yoki bazadanmi? Ishonchli javob: ekran faqat bazani kuzatadi. Repozitoriy tarmoqdan yangi ma'lumot olganda uni bazaga yozadi, va Room Flow uni ekranga o'zi yetkazadi. Baza bitta haqiqat manbai (single source of truth): ekranda ziddiyatli ikki manba yo'q, internet yo'q paytda oxirgi ma'lum holat ko'rinadi, va ilova ochilishi bilan kesh darhol chiqadi.

Migratsiyalar

Ilovaning yangi versiyasida jadvalga ustun qo'shildi. Foydalanuvchi qurilmasida esa eski sxemali baza va unda ma'lumot bor. Room versiya raqamlarini solishtiradi: version oshgan, demak migratsiya kerak.

  • Qo'lda migratsiya: val M1_2 = object : Migration(1, 2) { override fun migrate(db) { db.execSQL("ALTER TABLE cards ADD COLUMN currency TEXT NOT NULL DEFAULT 'UZS'") } }.
  • Avtomatik migratsiya: @Database(autoMigrations = [AutoMigration(from = 1, to = 2)]): Room eksport qilingan sxema JSON fayllarini solishtirib, oddiy o'zgarishlar (ustun qo'shish) uchun SQL ni o'zi yozadi. Buning uchun exportSchema = true va sxema fayllari repozitoriyda saqlanadi.
  • Migratsiya topilmasa: Room IllegalStateException bilan qulaydi, yangilangan ilova ochilmaydi. fallbackToDestructiveMigration() buning o'rniga bazani o'chirib, qaytadan yaratadi: kesh uchun qabul qilinadi, lekin foydalanuvchi qoralamalari va sozlamalari yo'qoladi.
  • Test: MigrationTestHelper eski versiyali bazani yaratib, ma'lumot qo'yib, migratsiyani bajaradi va natijani tekshiradi.

DataStore

DataStore ikki xil:

  • Preferences DataStore: kalit-qiymat, lekin kalitlar tur bilan: val TIL = stringPreferencesKey("til"). O'qish dataStore.data.map { it[TIL] ?: "uz" } (Flow), yozish dataStore.edit { it[TIL] = "ru" } (suspend, tranzaksiya: blok ichidagi barcha o'zgarishlar birga yoziladi yoki hech biri).
  • Proto DataStore: butun sozlamalar bitta turlangan obyekt (protobuf yoki kotlinx.serialization bilan): data class Sozlamalar(val til: String, val balansYashirin: Boolean). updateData { it.copy(...) }. Tur xavfsizligi to'liq.

Qoidalar: bitta fayl uchun faqat bitta DataStore nusxasi (ilova bo'yicha singleton, A6), aks holda IllegalStateException. SharedPreferences'dan ko'chish uchun SharedPreferencesMigration. DataStore o'zi shifrlamaydi: maxfiy narsa uchun A12.

5. AmaliyotdaTuzoqlar

Tuzoq: migratsiyasiz versiya

Dasturchi Entity'ga maydon qo'shdi, versiyani oshirdi, lekin migratsiya yozmadi. O'z qurilmasida ilovani o'chirib qayta o'rnatgani uchun hammasi ishladi. Do'kondan yangilangan foydalanuvchilarda esa ilova ochilishda qulaydi.

Har bir sxema o'zgarishi: versiya, migratsiya (yoki AutoMigration), sxema fayli repozitoriyda va MigrationTestHelper testi. Kod ko'rib chiqishda sxema JSON fayli o'zgargan bo'lsa, migratsiya ham bo'lishi shart.

Tuzoq: o'ziga kerak bo'lmagan jadvalni kuzatish

Kartalar ekranining so'rovi operatsiyalar jadvaliga JOIN qiladi. Har yangi operatsiya kelganda kartalar Flow i ham qayta so'raydi, chunki Room jadval darajasida kuzatadi. Ko'p yozuvli ekranlarda bu ortiqcha ish va keraksiz rekompozitsiya.

Ekran faqat kerakli jadvallarni o'qisin; Flow'ga distinctUntilChanged() qo'shing (A4): natija o'zgarmagan bo'lsa, ekran yangilanmaydi.

Tuzoq: bir faylga ikki DataStore

DataStore'ni har safar PreferenceDataStoreFactory.create(...) bilan yoki ikki joyda preferencesDataStore delegati bilan yaratish: bir faylda ikki nusxa, IllegalStateException yoki ma'lumot yo'qolishi.

DataStore ilova bo'yicha bitta, DI orqali single (A6).

Qoida: pulni REAL ustunda saqlamang

SQLite'ning REAL turi 3-darsdagi double. Balans va summalar INTEGER (tiyinda) yoki TEXT (BigDecimal satri) ustunda.

Oracle'dagi NUMBER(19,2) qoidasining mobil ko'rinishi.

6. SuhbatdaSavol va namunaviy javoblar

Room nima va SQLiteOpenHelper'dan nimasi yaxshi?

SQLite ustidagi abstraksiya: Entity, DAO, Database. SQL kompilyatsiyada tekshiriladi, mapping kodi yaratiladi, suspend va Flow qo'llab-quvvatlanadi, asosiy oqimda so'rovga sukut bo'yicha ruxsat bermaydi, migratsiya va sxema eksporti bor, InvalidationTracker orqali o'zgarishlarni xabar qiladi.

Room Flow qanday qilib yangi ma'lumotni chiqaradi?

InvalidationTracker SQLite triggerlari bilan o'zgargan jadvallarni belgilaydi. Yozuvchi tranzaksiya tugagach, shu jadvallarni o'qiydigan Flow lar so'rovni qayta bajaradi va yangi natijani chiqaradi. Kuzatuv jadval darajasida, shuning uchun natija o'zgarmagan bo'lsa ham chiqishi mumkin: distinctUntilChanged.

Migratsiya nima? U bo'lmasa nima bo'ladi?

Versiya oshganda eski bazani ma'lumotini saqlab yangi sxemaga o'tkazish: qo'lda Migration(from, to) SQL bilan yoki AutoMigration eksport qilingan sxemalar asosida. Migratsiya topilmasa, Room IllegalStateException bilan qulaydi; fallbackToDestructiveMigration bazani o'chiradi va ma'lumot yo'qoladi. MigrationTestHelper bilan testlanadi.

Oflayn rejimni qanday qilasiz?

Bitta haqiqat manbai: ekran faqat Room Flow ni kuzatadi; repozitoriy tarmoqdan yangilaganda bazaga yozadi. Internet yo'q bo'lsa, ekranda oxirgi kesh va «yangilanmadi» belgisi. Yozish amallari (masalan qoralama) navbatga qo'yilib, WorkManager bilan tarmoq paydo bo'lganda yuboriladi. Pul o'tkazmasini oflayn navbatga qo'yish esa xavfli va odatda qilinmaydi.

DataStore va SharedPreferences farqi? Preferences va Proto farqi?

DataStore asinxron (Flow, suspend), asosiy oqimni bloklamaydi, tranzaksiyali, xatolarni ochiq beradi, tur xavfsiz kalitlar. SharedPreferences sinxron o'qiydi, apply ANR ga olib kelishi mumkin, tranzaksiya yo'q. Preferences DataStore: turlangan kalit-qiymat. Proto DataStore: butun sozlamalar bitta turlangan obyekt, protobuf yoki kotlinx.serialization bilan.

Tokenni qayerda saqlaysiz?

Shifrsiz SharedPreferences yoki DataStore'da emas. Refresh token Android Keystore'dagi kalit bilan shifrlanib (Tink bilan, DataStore yoki faylda) saqlanadi; EncryptedSharedPreferences endi eskirgan deb belgilangan. Access token iloji boricha faqat xotirada. Batafsil A12 da.

Room 3.0 haqida eshitganmisiz?

2026-yil martida birinchi alfa chiqdi: faqat KSP va faqat Kotlin, DAO metodlari suspend yoki Flow bo'lishi shart (bloklovchi metodlar yo'q), to'liq SQLiteDriver API ustida (Multiplatform, veb ham), paket nomi androidx.room3 ga o'zgaradi. Room 2.x texnik qo'llab-quvvatlash rejimida. (Holatini suhbatdan oldin tekshiring.)

7. Tekshiruv

  1. Kartalar ekrani uchun Entity, DAO metodlari va repozitoriyning ishlash tartibini tasvirlang.
  2. Yangi versiyada operatsiyalar jadvaliga «kategoriya» ustuni qo'shildi. Qadamlaringiz?
  3. Operatsiya qo'shilganda kartalar ekrani ham qayta chizilyapti. Sababi va yechimi?
  4. «Balansni yashirish» sozlamasini qayerda saqlaysiz va ekran uni qanday oladi?
  5. Oracle tajribangizdan qaysi bilimlar Room bilan ishlashda yordam beradi?

Chuqurroq

WAL rejimi va bir vaqtda o'qish

Room SQLite'ni sukut bo'yicha WAL (write-ahead logging) rejimida ochadi: yozish alohida jurnalga ketadi, shuning uchun o'qishlar yozish paytida ham bloklanmaydi. Bu P0 ning 5-darsidagi «ketma-ket yozish tez» g'oyasining amaliy ko'rinishi va Oracle'dagi redo log ga o'xshaydi.
