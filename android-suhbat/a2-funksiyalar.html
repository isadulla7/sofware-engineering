A2. Funksiyalar: lambda, inline, crossinline, reified, scope funksiyalar

Savol: Kotlin'da funksiya qiymat sifatida qanday uzatiladi, bu qancha turadi, va inline, noinline, crossinline, reified nima uchun kerak?

Bu nima

Lambda nomsiz funksiya, uni o'zgaruvchiga saqlash va boshqa funksiyaga argument qilib berish mumkin: kartalar.filter { it.balans > 0 }. Funksiyani argument sifatida oladigan funksiya yuqori tartibli funksiya deyiladi.

inline kompilyatorga «bu funksiyani chaqirma, uning tanasini chaqirilgan joyga ko'chirib qo'y» deydi. Qolgan kalit so'zlar shu ko'chirishning nozik joylarini boshqaradi.

Qayerda ishlatiladi

  • Hamma joyda. map, filter, forEach, let, apply, use, synchronized: hammasi lambda oladigan inline funksiyalar.
  • Compose'da: har bir @Composable ekran lambdalardan quriladi: onClick = { ... }, Column { ... }.
  • Koin, Ktor, Gradle: module { single { ... } } kabi DSL lar qabul qiluvchili lambdalarga qurilgan.
  • Suhbatda: «inline, noinline, crossinline farqi» klassik savol, o'tgan suhbatda ham so'ralgan.

Bu darsning maqsadi

  • lambda ichkarida nimaga aylanishi va qachon obyekt yaratilishi;
  • inline nimani yutadi va nimani yo'qotadi;
  • lokal bo'lmagan return, noinline, crossinline;
  • tur o'chirilishi va reified;
  • let, run, with, apply, also farqi va qaysi biri qachon.

Bu dars qamraydi

  • Funksiya turlari va yuqori tartibli funksiyalar
  • Lambda baytkodda: obyekt, ushlangan o'zgaruvchilar
  • inline, lokal bo'lmagan qaytish, noinline, crossinline
  • reified tur parametrlari
  • Qabul qiluvchili lambda va scope funksiyalar
  • fun interface (SAM)

Bu darsga kirmaydi

  • suspend lambdalar va coroutines: A3-darsda
  • Compose'dagi lambdalar barqarorligi va rekompozitsiya: A7-darsda

1. Og'riqFunksiyani uzatish qimmat edi

Java 8 gacha funksiyani boshqa funksiyaga berishning yagona yo'li anonim klass edi. Tugma bosilishini tinglash uchun besh-olti qator yozilardi: new View.OnClickListener() { @Override public void onClick(View v) { ... } }. Kod ko'p, va har bir shunday joy alohida klass faylga, xotirada esa alohida obyektga aylanardi.

Kotlin bu yozuvni bitta qavsga qisqartirdi: setOnClickListener { ... }. Lekin muammo qisman qoldi: lambda baribir obyekt. filter, map, forEach kabi funksiyalar har qadamda chaqiriladi, va har birida yangi obyekt yaratish, virtual chaqiruv qilish kichik, lekin hamma joyda to'lanadigan narx. Kotlin uni inline bilan butunlay yo'qotishni taklif qildi, va bu qaror o'z navbatida yangi savollarni keltirib chiqardi: return qayerdan qaytadi, lambdani saqlab qo'yish mumkinmi, tur ma'lumoti qayerda.

2. IchkaridaLambda va inline

Lambda bu obyekt

Kotlin'da funksiya ham tur: (Karta) -> Boolean «karta olib, mantiqiy qiymat qaytaradigan funksiya». Baytkodda bu Function1<Karta, Boolean> interfeysi, uning bitta invoke metodi bor. Lambda yozilgan joyda kompilyator shu interfeysni amalga oshiradigan obyektni yaratadi. Agar lambda tashqi o'zgaruvchidan foydalansa (uni ushlasa), o'sha o'zgaruvchi obyektning maydoniga ko'chiriladi, va har bir chaqiruvda yangi obyekt yaratiladi. Hech narsa ushlamaydigan lambda esa bitta umumiy nusxa bo'lib qoladi.

Tasavvur qilish uchun. Oshpazga «qovurib ber» degan harakatni qo'lga tutqazib bo'lmaydi. Unga kartochka berasiz: kartochkada nima qilish yozilgan, oshpaz kerak paytda uni o'qib bajaradi. JVM ham xuddi shunday: u funksiyalarga faqat narsalarni, ya'ni obyektlarni bera oladi. Shuning uchun «kartani tekshir» degan amalni filter ga berish uchun kompilyator uni kartochkaga, ya'ni obyektga aylantiradi. Kartochkada bitta «bajar» tugmasi bor: bu invoke. Pastdagi chizmani qadamma-qadam bosing: chapda siz yozgan kod, o'rtada kompilyator undan yasagan klass, o'ngda dastur ishlaganda xotirada paydo bo'ladigan obyektlar.

Pastdagi chizmada bitta chaqiruv ikki usulda: filter oddiy funksiya bo'lsa va inline bo'lsa.

inline ning yutug'i: lambda obyekti yo'q, virtual chaqiruv yo'q, kompilyator ko'chirilgan kodni birga optimallashtiradi. Narxi: funksiya tanasi har bir chaqirilgan joyga ko'chirilgani uchun kod hajmi o'sadi. Shuning uchun inline faqat lambda oladigan kichik funksiyalar uchun. Lambda olmaydigan funksiyaga inline qo'ysangiz, kompilyator «foydasi kam» deb ogohlantiradi. Yana bir cheklov: ochiq (public) inline funksiya klassning yopiq (private) a'zolariga murojaat qila olmaydi, chunki uning tanasi boshqa modullarga ko'chiriladi.

return qayerdan qaytadi: lokal bo'lmagan qaytish

Lambda tanasi chaqirilgan joyga ko'chirilsa, uning ichidagi return endi tashqi funksiyaning return i bo'lib qoladi. Bu lokal bo'lmagan qaytish deyiladi. U faqat inline funksiyaga berilgan lambdada ruxsat etiladi. Oddiy lambdada faqat yorliqli qaytish mumkin: return@forEach, u lambdaning o'zidan chiqadi, xolos.

Ikki kalit so'z shu xatti-harakatni boshqaradi:

  • noinline: inline funksiyaning bitta lambda parametrini ko'chirmaslik. Kerak bo'ladi, agar lambdani saqlab qo'yish yoki boshqa oddiy funksiyaga uzatish zarur bo'lsa: ko'chirilgan kodni o'zgaruvchiga saqlab bo'lmaydi, unga obyekt kerak.
  • crossinline: lambda ko'chiriladi, lekin u boshqa kontekstda bajariladi, masalan Runnable ichida, boshqa lambda ichida yoki keyinroq. U yerdan tashqi funksiyaga return qilish mantiqsiz, chunki tashqi funksiya allaqachon tugagan bo'lishi mumkin. crossinline shunday return ni taqiqlaydi va kompilyatorga lambdani boshqa kontekstga ko'chirishga ruxsat beradi.

reified: o'chirilgan turni qaytarish

A1-darsda aytilgandek, JVM da generik tur ish paytida o'chiriladi. fun <T> parse(json: String): T ichida T qaysi klass ekanini bilib bo'lmaydi, shuning uchun Gson'ga klassni alohida berish kerak: parse(json, Karta::class.java). inline funksiyada esa tana chaqirilgan joyga ko'chiriladi, va u yerda T aniq: Karta. reified kalit so'zi kompilyatorga «ko'chirganda T o'rniga haqiqiy klassni qo'y» deydi. Shundan keyin funksiya ichida T::class va x is T ishlaydi.

Android'da ko'p uchraydigan misollar: koinViewModel<KartalarViewModel>() va get<CardRepository>() (Koin aynan shu yo'l bilan klassni topadi), startActivity<DetailActivity>() kabi yordamchilar, JSON dan o'qish yordamchilari.

Qabul qiluvchili lambda va scope funksiyalar

Lambda turining yana bir ko'rinishi bor: Karta.() -> Unit. Bu «qabul qiluvchili» lambda: uning ichida this o'sha Karta, va uning a'zolariga nuqtasiz murojaat qilinadi. apply, buildString, Koin'ning module { }, Compose'ning Column { } shunga qurilgan.

Standart kutubxonada beshta «scope funksiya» bor. Ularning hammasi obyekt ustida blok bajaradi, va ikki savol bilan farqlanadi: blok ichida obyekt this mi yoki it mi, va funksiya nima qaytaradi: obyektning o'zini yoki blok natijasini.

fun interface

Java'dagi bitta metodli interfeysga (Runnable, OnClickListener) Kotlin lambdasi to'g'ridan-to'g'ri beriladi: bu SAM konversiya («yagona abstrakt metod»). Kotlin'ning o'z interfeyslari uchun ham shunday qilish uchun ular fun interface deb e'lon qilinadi: fun interface KartaTanlandi { fun tanlandi(k: Karta) }. Oddiy funksiya turidan ((Karta) -> Unit) farqi: nomi bor, hujjatlashtiriladi va Java'dan qulay chaqiriladi.

4. Atamalar

Yuqori tartibli funksiya
Funksiyani argument sifatida oladigan yoki funksiya qaytaradigan funksiya.
Funksiya turi
(A) -> B ko'rinishidagi tur. Baytkodda Function1<A, B> kabi interfeys.
Ushlash (capture)
Lambdaning tashqi o'zgaruvchidan foydalanishi. Ushlagan lambda har safar yangi obyekt bo'ladi.
inline
Funksiya va unga berilgan lambdalar tanasini chaqirilgan joyga ko'chirish.
Lokal bo'lmagan qaytish
inline funksiyaga berilgan lambda ichidagi return tashqi funksiyadan chiqadi.
Yorliqli qaytish
return@forEach: faqat lambdaning o'zidan chiqish.
noinline
inline funksiyaning shu lambda parametrini ko'chirmaslik: u oddiy obyekt bo'lib qoladi va uni saqlash yoki uzatish mumkin.
crossinline
Lambda ko'chiriladi, lekin boshqa kontekstda bajariladi; ichida lokal bo'lmagan return taqiqlanadi.
reified
inline funksiyaning tur parametri: ko'chirishda haqiqiy klass bilan almashtiriladi, ichida T::class va is T ishlaydi.
Qabul qiluvchili lambda
T.() -> R: blok ichida this T obyekti. DSL lar asosi.
Scope funksiyalar
let, run, with, apply, also: obyekt ustida blok bajaradigan standart funksiyalar.
SAM konversiya, fun interface
Bitta abstrakt metodli interfeys o'rniga lambda berish. Kotlin interfeysi uchun fun interface deb e'lon qilinadi.

5. AmaliyotdaTuzoqlar

Tuzoq: forEach ichidagi return

kartalar.forEach { if (it.bloklangan) return } sikldan emas, butun funksiyadan chiqadi, chunki forEach inline. Dasturchi «bu kartani o'tkazib yuboraman» deb o'ylaydi, aslida qolgan kartalar ham, funksiyaning qolgan qismi ham bajarilmaydi.

Elementni o'tkazib yuborish uchun return@forEach (Java'dagi continue kabi). To'xtatish kerak bo'lsa, oddiy for sikli va break ancha tushunarli.

Tuzoq: lambda ushlab qolgan Activity

Lambda ushlagan o'zgaruvchilar lambda yashagancha yashaydi. Uzoq yashaydigan obyektga (singleton, statik ro'yxat, tarmoq so'rovining qayta chaqiruvi) berilgan lambda ichida this yoki Activity ga murojaat bo'lsa, ekran yopilgandan keyin ham u xotiradan tozalanmaydi: xotira oqishi.

Ekran bilan bog'liq ishlarni ekranning hayot sikliga bog'langan joyda bajarish: viewModelScope, lifecycleScope, Compose'da LaunchedEffect. Bular A3 va A7-darslarda.

Qoida: scope funksiyalarni zanjir qilib ketmang

a?.let { it.b?.also { ... }?.run { ... } } kabi zanjirlarda it va this nimani bildirayotganini o'quvchi yo'qotadi. Ichma-ich apply larda esa this eng ichkidagi obyekt, tashqi obyektning bir xil nomli xususiyati sezdirmasdan yopilib qoladi.

Bitta ifodada bitta scope funksiya, va oddiy if yoki o'zgaruvchi tushunarliroq bo'lsa, o'shani yozish. Kod ko'rib chiqishda shu ko'p so'raladi.

6. SuhbatdaSavol va namunaviy javoblar

inline funksiya nima va nima uchun kerak?

Kompilyator funksiyani chaqirish o'rniga uning tanasini va unga berilgan lambdalar tanasini chaqirilgan joyga ko'chiradi. Natijada lambda uchun obyekt yaratilmaydi va virtual chaqiruv yo'q, bu tez-tez chaqiriladigan yuqori tartibli funksiyalarda (map, filter, let) muhim. Qo'shimcha imkoniyatlar: lokal bo'lmagan return va reified tur parametrlari. Narxi: kod hajmi o'sadi, shuning uchun faqat kichik va lambda oladigan funksiyalar uchun.

noinline va crossinline farqi nima?

Ikkalasi ham inline funksiyaning lambda parametriga qo'yiladi. noinline: shu lambda umuman ko'chirilmaydi, oddiy obyekt bo'lib qoladi; kerak, agar lambdani o'zgaruvchida saqlash yoki inline bo'lmagan funksiyaga uzatish kerak bo'lsa. crossinline: lambda ko'chiriladi, lekin boshqa kontekstda bajariladi (boshqa lambda, Runnable, obyekt ichida), shuning uchun undan lokal bo'lmagan return taqiqlanadi. Qisqasi: noinline «ko'chirma», crossinline «ko'chir, lekin tashqi funksiyadan qaytishga ruxsat berma».

Lokal bo'lmagan return nima? Nega oddiy lambdada ruxsat yo'q?

inline funksiyaga berilgan lambda tanasi chaqirilgan joyga ko'chiriladi, shuning uchun undagi return tashqi funksiyadan chiqadi. Oddiy lambda esa obyekt, u istalgan vaqtda, hatto tashqi funksiya tugaganidan keyin chaqirilishi mumkin, u holda «tashqi funksiyadan qaytish»ning ma'nosi yo'q. Oddiy lambdadan faqat yorliqli return@yorliq bilan chiqiladi.

reified nima? Nega u faqat inline bilan ishlaydi?

JVM da generik turlar ish paytida o'chiriladi, funksiya ichida T ning klassi noma'lum. inline funksiya chaqirilgan joyga ko'chirilgani uchun u yerda tur aniq, va reified kompilyatorga T ni haqiqiy klass bilan almashtirishni aytadi. Shundan keyin T::class, is T, as T ishlaydi. Oddiy funksiya bitta nusxa bo'lib, hamma chaqiruvlar uchun umumiy, unda bunday almashtirishning iloji yo'q. Misol: Koin'dagi get<T>(), koinViewModel<T>().

let, run, with, apply, also farqi?

Ikki o'lchov. Obyekt blok ichida: it (let, also) yoki this (run, with, apply). Qaytaradi: blok natijasini (let, run, with) yoki obyektning o'zini (apply, also). Odatiy ishlatilishi: ?.let null bo'lmasa biror narsa qilish yoki aylantirish; apply obyektni sozlash (builder o'rnida); also yon ish, masalan log yozish; run obyekt ustida hisoblab natija olish; with bitta obyekt ustida bir nechta chaqiruv, kengaytma emas.

Lambda xotirada nima? Har safar yangi obyekt yaratiladimi?

Inline bo'lmagan joyda lambda FunctionN interfeysini amalga oshiradigan obyekt. Agar u tashqi o'zgaruvchilarni ushlasa, har chaqiruvda ular bilan yangi obyekt yaratiladi; ushlamasa, bitta umumiy nusxa ishlatiladi. Kotlin 2.0 dan boshlab JVM uchun lambdalar sukut bo'yicha invokedynamic orqali yaratiladi (Java 8 lambdalari kabi), oldin har biri alohida anonim klass edi; Android'da D8 buni yana klasslarga aylantiradi. Inline funksiyaga berilganda esa obyekt umuman yo'q.

Qachon inline qilmaslik kerak?

Funksiya katta bo'lsa yoki ko'p joyda chaqirilsa: kod hajmi o'sadi. Lambda parametri bo'lmasa: foydasi deyarli yo'q, kompilyator ogohlantiradi. Funksiya klassning private a'zolariga murojaat qilishi kerak bo'lsa: ochiq inline funksiya buni qila olmaydi. Rekursiv funksiyani inline qilib bo'lmaydi.

7. Tekshiruv

  1. Quyidagi kod nimani chop etadi va nega? fun f() { listOf(1, 2, 3).forEach { if (it == 2) return; print(it) }; print("oxiri") }
  2. O'zingiz inline fun ishlat(blok: () -> Unit) yozdingiz va ichida handler.post { blok() } chaqirdingiz. Kompilyator xato beradi. Nega va qanday tuzatiladi?
  3. Nega fun <T> isType(x: Any) = x is T kompilyatsiya bo'lmaydi va qanday tuzatiladi?
  4. Retrofit so'rovini sozlashda apply, javobni ekran modeliga aylantirishda let. Nega aynan shular?

Chuqurroq

Funksiyaga havola va inline xususiyatlar

kartalar.map(Karta::raqam): mavjud funksiya yoki xususiyatga havola lambda o'rnida ishlatiladi. Xususiyatlar ham inline bo'lishi mumkin, agar ularda saqlanadigan maydon bo'lmasa: getter va setter chaqirilgan joyga ko'chiriladi.

Birlamchi manbalar

Kotlin hujjatlari: «Higher-order functions and lambdas», «Inline functions», «Scope functions» (kotlinlang.org/docs). Kotlin 2.0 da lambdalarning invokedynamic bilan yaratilishi: «What's new in Kotlin 2.0.0».

Bu darsdan olib ketadigan narsa. Lambda obyekt, ushlasa har safar yangi. inline funksiya va lambda tanasini chaqirilgan joyga ko'chiradi: obyekt yo'q, lokal bo'lmagan return bor, reified ishlaydi, kod hajmi o'sadi. noinline ko'chirmaydi, crossinline ko'chiradi lekin return ni taqiqlaydi. Scope funksiyalar this/it va nima qaytarishi bilan farqlanadi.
