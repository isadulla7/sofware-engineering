A8. Navigatsiya: Navigation Compose va Navigation 3

Savol: ekranlar orasida qanday o'tiladi, orqaga qaytish tarixi qayerda saqlanadi, argumentlar qanday beriladi, va Navigation 3 nimani o'zgartirdi?

Bu nima

Navigatsiya: ekranlar orasida o'tish va orqaga qaytish steki (back stack), ya'ni ochilgan ekranlar ro'yxati. Orqaga tugmasi stekning oxirgi elementini olib tashlaydi.

Navigation Compose (Navigation 2): stekni NavController ichkarida boshqaradi. Navigation 3 (2025-yil noyabrda barqaror 1.0): stek sizning oddiy ro'yxatingiz, NavDisplay esa uni kuzatib, ekranni ko'rsatadi.

Qayerda ishlatiladi

  • Vakansiyada: «zamonaviy navigatsiya yondashuvlarini bilish (Navigation3 / Compose Navigation)».
  • Bank ilovasida: kirish va PIN oqimi, asosiy ekranlar, o'tkazma bosqichlari, push xabardan to'g'ridan-to'g'ri ekran ochish.
  • Suhbatda: «argumentlarni qanday berasiz», «login'dan keyin orqaga qaytmaslik», «Navigation 3 nima uchun».

Bu darsning maqsadi

  • orqaga qaytish steki va asosiy amallar: o'tish, qaytish, popUpTo, launchSingleTop;
  • Navigation Compose: tur xavfsiz marshrutlar, argumentlar, ichki graflar, chuqur havolalar;
  • Navigation 3: NavKey, rememberNavBackStack, NavDisplay, entryProvider, dekoratorlar, sahnalar;
  • ViewModel ekran yozuviga qanday bog'lanadi;
  • bank ilovasiga xos oqimlar.

Bu dars qamraydi

  • Activity va Fragment davridagi og'riq
  • Orqaga qaytish steki
  • Navigation Compose 2.8+ tur xavfsiz marshrutlar bilan
  • Navigation 3: tuzilishi, dekoratorlar, sahnalar
  • Argumentlar, natija qaytarish, ViewModel'ni ekranga bog'lash
  • Kirish oqimi va chuqur havolalar

Bu darsga kirmaydi

  • Fragment'lar va XML navigatsiya grafi batafsil
  • O'tish animatsiyalari

1. Og'riqEkranlar orasidagi yo'l

Android'ning dastlabki yillarida har bir ekran alohida Activity edi. O'tish Intent bilan, argumentlar putExtra bilan kalit-qiymat ko'rinishida, turlar tekshirilmasdan. Stekni tizim boshqarardi, uni o'zgartirish uchun FLAG_ACTIVITY_CLEAR_TOP kabi bayroqlar kombinatsiyasi kerak edi, va ularning xatti-harakati ko'pincha kutilmagan bo'lardi.

Keyin Fragment'lar keldi: bitta Activity ichida ko'p ekran. Lekin FragmentManager tranzaksiyalari, o'z stek mantiqi va murakkab hayot sikli eng ko'p xato chiqaradigan joylardan biriga aylandi. 2018-yildagi Navigation Component XML graf va Safe Args bilan buni tartibga soldi, Compose bilan esa NavHost paydo bo'ldi.

Compose navigatsiyasining birinchi versiyasida marshrutlar satr edi: "detail/{id}", argumentlar qo'lda o'qilardi, xato faqat ish paytida chiqardi. Va asosiy cheklov qoldi: stek NavController ichida yashirin. Compose'da hamma narsa holat, faqat navigatsiya steki boshqa qoidalarga bo'ysunadigan qora quti edi. Planshet va bukiladigan telefonlarda ikki ekranni yonma-yon ko'rsatish (ro'yxat va tafsilot) uni qiyinlashtirardi.

2. IchkaridaStek va uni kim boshqaradi

Orqaga qaytish steki

Navigatsiyaning asosi bitta tushuncha: ochilgan ekranlar ro'yxati. Yangi ekranga o'tish ro'yxat oxiriga qo'shadi, orqaga qaytish oxirgisini olib tashlaydi, ko'rinadigan ekran doim oxirgisi. Qolgan hamma narsa shu ro'yxat ustidagi amallar. Pastda bank ilovasidagi odatiy oqimni bajaring.

Navigation Compose: tur xavfsiz marshrutlar

Navigation 2.8 (2024) dan boshlab marshrutlar satr emas, @Serializable Kotlin turlari:

@Serializable object Kartalar
@Serializable data class KartaDetail(val id: String)

NavHost(navController, startDestination = Kartalar) {
    composable<Kartalar> { KartalarEkran(onOpen = { id -> navController.navigate(KartaDetail(id)) }) }
    composable<KartaDetail> { KartaDetailEkran() }
}
// ViewModel ichida argumentni olish:
class KartaDetailViewModel(handle: SavedStateHandle, ...) : ViewModel() {
    private val id = handle.toRoute<KartaDetail>().id
}
  • NavController stekni saqlaydi va boshqaradi: navigate, popBackStack, navigateUp.
  • Stekning har bir yozuvi (NavBackStackEntry) o'z hayot sikliga, ViewModelStore ga va SavedStateHandle ga ega. Shuning uchun ekranning ViewModel'i u stekda turgan ekan yashaydi va olib tashlanganda tozalanadi. Argumentlar SavedStateHandle ga avtomatik yoziladi.
  • Ichki graflar: navigation<OtkazmaGraf>(startDestination = Summa) { ... }. Bir nechta bosqichli oqim (summa, tasdiqlash, natija) bitta guruh; graf darajasidagi umumiy ViewModel bilan bosqichlar ma'lumot bo'lishadi.
  • Natija qaytarish: oldingi yozuvning savedStateHandle ga qiymat yozish (previousBackStackEntry?.savedStateHandle?.set(...)).
  • Chuqur havolalar: deepLinks = listOf(navDeepLink<OtkazmaDetail>(basePath = "bank://transfer")).

Navigation 3: stek sizniki

Navigation 3 boshqa g'oyadan boshlanadi: stek oddiy Compose holati, va siz uni o'zingiz o'zgartirasiz. Kutubxona faqat shu ro'yxatni kuzatib, oxirgi elementni (yoki sahnaga qarab bir nechtasini) ko'rsatadi.

@Serializable data object Kartalar : NavKey
@Serializable data class KartaDetail(val id: String) : NavKey

@Composable
fun BankNav() {
    val backStack = rememberNavBackStack(Kartalar)       // konfiguratsiya va jarayon o'limidan omon qoladi
    NavDisplay(
        backStack = backStack,
        onBack = { backStack.removeLastOrNull() },
        entryDecorators = listOf(
            rememberSaveableStateHolderNavEntryDecorator(),
            rememberViewModelStoreNavEntryDecorator()     // har bir yozuvga o'z ViewModelStore
        ),
        entryProvider = entryProvider {
            entry<Kartalar> { KartalarEkran(onOpen = { backStack.add(KartaDetail(it)) }) }
            entry<KartaDetail> { key -> KartaDetailEkran(key.id) }
        }
    )
}
  • NavKey: ekran kaliti. @Serializable bo'lsa, rememberNavBackStack stekni saqlab qo'yadi: aylantirish va jarayon o'limidan omon qoladi.
  • entryProvider: kalitni ekranga aylantiradigan funksiya. Argumentlar kalitning maydonlari: tur xavfsiz, hech qanday satr tahlili yo'q.
  • Dekoratorlar: har bir yozuvga qo'shimcha imkoniyat qo'shadi. rememberSaveableStateHolderNavEntryDecorator() ekranning rememberSaveable holatini saqlaydi, rememberViewModelStoreNavEntryDecorator() (lifecycle-viewmodel-navigation3 artefaktidan) har bir yozuvga o'z ViewModelStore beradi: ViewModel kalit stekka qo'shilganda yaratiladi va olib tashlanganda tozalanadi. Bu dekorator LocalViewModelStoreOwner ni beradi, shuning uchun yozuv ichidagi viewModel() (va xuddi shu mexanizmga tayanadigan Koin'ning koinViewModel()) shu yozuvga bog'lanadi.
  • Sahnalar (Scenes): bir vaqtda bir nechta yozuvni ko'rsatish strategiyasi. Masalan, keng ekranda stekning oxirgi ikki yozuvi (ro'yxat va tafsilot) yonma-yon. Navigation 2 da buni qilish qiyin edi, chunki u faqat bitta joriy ekranni bilardi.
  • Natija qaytarish va bir nechta stek (pastki panelning har bir yorlig'i uchun alohida tarix) oddiy Kotlin kodi bilan yoziladi: masalan, har bir yorliq uchun alohida ro'yxat.

Navigation 2 eskirmagan va ko'p loyihalarda ishlaydi. Navigation 3 yangi loyihalar va moslashuvchan (planshet, bukiladigan) ekranlar uchun. Suhbatda ikkalasini bilish va farqini aytish kerak.

Bank ilovasiga xos oqimlar

  • Kirish oqimi: PIN yoki biometriya muvaffaqiyatli bo'lgach, kirish ekranlari stekdan butunlay olib tashlanadi, aks holda «orqaga» foydalanuvchini PIN ekraniga qaytaradi. Navigation 2: navigate(Asosiy) { popUpTo(Kirish) { inclusive = true } }. Navigation 3: backStack.clear(); backStack.add(Asosiy).
  • Sessiya tugashi: token muddati o'tganda (A9) istalgan ekrandan kirishga qaytish va stekni tozalash.
  • Push xabardan ochish: «Kartangizga pul tushdi» bosilganda tafsilot ekrani ochilishi kerak, lekin avval foydalanuvchi PIN kiritgan bo'lishi shart va orqaga bosilganda asosiy ekranga qaytishi kerak. Ya'ni stek qo'lda yig'iladi: Asosiy, keyin Tafsilot.
  • O'tkazma bosqichlari: muvaffaqiyatli o'tkazmadan keyin «orqaga» tasdiqlash ekraniga qaytarmasligi kerak, aks holda foydalanuvchi to'lovni takrorlab yuborishi mumkin.

3. Yaratilishi va o'zgarishiAndroid navigatsiyasi tarixi

4. Atamalar

Orqaga qaytish steki
Ochilgan ekranlar ro'yxati; ko'rinadigani oxirgisi, orqaga tugmasi oxirgisini olib tashlaydi.
Marshrut (route), kalit (key)
Ekranni va uning argumentlarini ifodalaydigan obyekt. Navigation 2.8+ va Navigation 3 da @Serializable Kotlin turi.
NavController, NavHost
Navigation 2: stekni ichkarida boshqaradigan obyekt va grafni ko'rsatadigan composable.
NavBackStackEntry
Navigation 2 stekining yozuvi: argumentlar, hayot sikli, ViewModelStore, SavedStateHandle.
popUpTo, inclusive, launchSingleTop
O'tishda stekni ma'lum ekrangacha tozalash; shu ekranni ham olib tashlash; bir xil ekranni ustma-ust qo'ymaslik.
Ichki graf
Bir nechta ekrandan iborat guruh (o'tkazma oqimi), o'z boshlang'ich ekrani va umumiy ViewModel bilan.
Chuqur havola (deep link)
Tashqaridan (push, havola) ma'lum ekranni ochish manzili.
NavKey, NavBackStack, rememberNavBackStack
Navigation 3: ekran kaliti, kalitlar ro'yxati va uni saqlanadigan qilib yaratish.
NavDisplay, entryProvider, NavEntry
Navigation 3: stekni kuzatib ko'rsatadigan composable, kalitni ekranga aylantiruvchi, va bitta yozuv.
NavEntryDecorator
Yozuvga holat saqlash yoki ViewModelStore kabi imkoniyat qo'shadigan qatlam.
Sahna (Scene)
Navigation 3 da bir vaqtda bir nechta yozuvni qanday joylashtirishni belgilaydigan strategiya.

5. AmaliyotdaTuzoqlar

Tuzoq: katta obyektni argument qilib berish

navigate(KartaDetail(karta)) ga butun Karta obyekti, ro'yxati va rasmlari bilan. Argumentlar saqlanadigan holatga (Bundle) yoziladi, uning hajmi cheklangan: katta bo'lsa TransactionTooLargeException, va ma'lumot eskirib qoladi.

Faqat identifikator beriladi, tafsilot ekranining ViewModel'i ma'lumotni repozitoriydan (keshdan) o'zi oladi. Bu ekranni chuqur havoladan ochishni ham osonlashtiradi.

Tuzoq: ViewModel ichida NavController

ViewModel'ga NavController berish: u ekrandan uzoq yashaydi, ekran o'zgarganda eski kontrollerni ushlab qoladi, va ViewModel'ni testlash qiyinlashadi.

ViewModel navigatsiya niyatini effekt sifatida yuboradi (A4, A5), ekran yoki navigatsiya qatlami uni bajaradi. Navigation 3 da stek holat bo'lgani uchun uni alohida «navigator» klassida saqlab, DI orqali berish ham mumkin.

Tuzoq: ikki marta bosish

Foydalanuvchi tugmani tez ikki marta bosdi: stekka bir xil ekran ikki marta qo'shildi, orqaga bosganda yana o'sha ekran chiqadi.

Navigation 2 da launchSingleTop = true; Navigation 3 da oxirgi element bir xil bo'lsa qo'shmaslik. Tugmani ish tugaguncha o'chirib qo'yish ham yordam beradi.

6. SuhbatdaSavol va namunaviy javoblar

Compose'da navigatsiya qanday tashkil qilinadi?

Navigation Compose: NavHost va NavController, 2.8 dan tur xavfsiz @Serializable marshrutlar, composable<T>, argumentlar toRoute va SavedStateHandle orqali, ichki graflar, chuqur havolalar. Yangi yondashuv Navigation 3: stek ilovaning o'z holati (rememberNavBackStack), NavDisplay uni kuzatadi, entryProvider kalitni ekranga aylantiradi.

Navigation 3 nima uchun yaratilgan? Navigation 2 dan farqi?

Navigation 2 da stek NavController ichida yashirin, Compose holatiga mos emas edi; argumentlar uchun satr marshrutlar; moslashuvchan (ro'yxat va tafsilot yonma-yon) layoutlar qiyin. Navigation 3 da stek oddiy kuzatiladigan ro'yxat, uni o'zingiz o'zgartirasiz; kalitlar tur xavfsiz obyektlar; dekoratorlar bilan holat va ViewModel saqlanadi; sahnalar bilan bir vaqtda bir nechta ekran. Kutubxona kichik, almashtiriladigan qismlardan iborat. 1.0 barqaror versiyasi 2025-yil noyabrda chiqdi.

Ekranga argument qanday beriladi? ViewModel uni qanday oladi?

Navigation 2: marshrut klassining maydoni, ViewModel'da savedStateHandle.toRoute<KartaDetail>(). Navigation 3: kalitning maydoni, entry<KartaDetail> { key -> } ichida olinadi va ViewModel'ga parametr qilib beriladi (DI'da parametr sifatida: Koin'da parametersOf(key.id)). Faqat identifikator, katta obyekt emas.

Kirishdan keyin «orqaga» PIN ekraniga qaytarmasligi uchun nima qilasiz?

Navigation 2: navigate(Asosiy) { popUpTo(KirishGraf) { inclusive = true } }. Navigation 3: stekni tozalab, faqat asosiy ekranni qo'shish. Sessiya tugaganda ham shunday: stek tozalanib, kirish ekrani qo'yiladi.

ViewModel qaysi ekranga bog'lanadi va qachon tozalanadi?

Navigation 2: har bir NavBackStackEntry ViewModelStoreOwner; ekran stekda ekan ViewModel yashaydi, olib tashlanganda tozalanadi. Graf darajasida umumiy ViewModel uchun graf yozuvi owner sifatida beriladi. Navigation 3: rememberViewModelStoreNavEntryDecorator har bir yozuvga ViewModelStore beradi, kalit stekdan olib tashlanganda u tozalanadi.

Bir martalik navigatsiya hodisasini ViewModel'dan qanday yuborasiz?

ViewModel Channel orqali effekt yuboradi (yoki holatda belgi va «bajarildi» niyati), ekran uni LaunchedEffect ichida kuzatib, navigatsiyani bajaradi. ViewModel NavController'ni bilmaydi.

7. Tekshiruv

  1. O'tkazma: summa, tasdiqlash, natija. Natija ekranidan «orqaga» qayerga olib borishi kerak va buni qanday ta'minlaysiz?
  2. Push xabardan tranzaksiya tafsilotini ochish: foydalanuvchi hali PIN kiritmagan. Stek qanday ko'rinishda bo'lishi kerak?
  3. Navigation 3 da ViewModel ekranga qanday bog'lanadi?
  4. Nega argument sifatida faqat ID beriladi?
  5. DigitalBank'da navigatsiya qanday qilingan edi (Activity'lar, Fragment'lar, Navigation Component)?

Chuqurroq

Pastki panel va bir nechta stek

Pastki panelning har bir yorlig'i (Asosiy, Kartalar, To'lovlar) o'z tarixini saqlashi kerak: yorliqni almashtirib qaytganda o'sha joyda bo'lish. Navigation 2 da saveState/restoreState bayroqlari bilan; Navigation 3 da har bir yorliq uchun alohida ro'yxat va joriy yorliq holati.

Birlamchi manbalar

Android: «Jetpack Navigation 3 is stable» (2025-yil noyabr), «Navigation 3» va «Save and manage navigation state» qo'llanmalari, «Type safety in Kotlin DSL and Navigation Compose» (developer.android.com/guide/navigation). Navigation 3 tafsilotlari tez o'zgaradi: kodni yozishdan oldin joriy hujjatni tekshiring.

Bu darsdan olib ketadigan narsa. Navigatsiya bu stek ustidagi amallar. Navigation 2 da stek NavController ichida, marshrutlar 2.8 dan tur xavfsiz. Navigation 3 da stek sizning holatingiz, NavDisplay uni ko'rsatadi, dekoratorlar holat va ViewModel'ni yozuvga bog'laydi, sahnalar bir nechta ekranni yonma-yon qo'yadi. Argument faqat ID, ViewModel NavController'ni bilmaydi.
