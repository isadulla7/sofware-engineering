A9. Tarmoq: Retrofit va Ktor, JSON, xatolar, tokenlar

Savol: so'rov kodingizdan serverga va javob qaytib ekranga qanday yetib boradi, JSON qanday o'qiladi, xatolar qanday turlanadi, va tokenni yangilash bir vaqtda kelgan o'nta so'rov bilan qanday ishlaydi?

Bu nima

Retrofit: HTTP API ni Kotlin interfeysi sifatida e'lon qilish kutubxonasi. Ichkarida so'rovlarni OkHttp yuboradi. Ktor client: JetBrains'ning Kotlin uchun yozilgan, Multiplatform HTTP mijozi.

JSON ni Kotlin obyektiga aylantirish serializatsiya kutubxonasi ishi: kotlinx.serialization, Moshi yoki Gson. Token: server bergan, har bir so'rovga qo'shiladigan kirish kaliti (ko'pincha JWT).

Qayerda ishlatiladi

  • Vakansiyada: «REST API integratsiyasi (Retrofit/Ktor), JSON, tarmoq xatolarini qayta ishlash va tokenlar bilan ishlash».
  • Bank ilovasida: har bir ekran serverga boradi; sessiya tokenlari, qisqa muddatli access token va uni yangilash.
  • Sizning tajribangiz: JWT bilan REST integratsiyasi va backend tomonda Alipay OAuth token oqimi: suhbatda ikki tomonni ham ko'rganingizni ayting.

Bu darsning maqsadi

  • Retrofit va OkHttp qanday tuzilgan, interceptor zanjiri;
  • Ktor client va Retrofit farqi;
  • JSON kutubxonalari va Kotlin bilan tuzoqlar;
  • xatolar turlari va ularni ekranga yetkazish;
  • access va refresh token, Authenticator, bir vaqtdagi yangilash;
  • vaqt chegaralari, qayta urinish va idempotentlik.

Bu dars qamraydi

  • HTTP so'rov va javob tuzilishi qisqacha
  • Retrofit, OkHttp, interceptorlar, Authenticator
  • Ktor client: dvigatellar va plaginlar
  • kotlinx.serialization, Moshi, Gson
  • Xatolar ierarxiyasi va natija turi
  • Tokenlar, JWT tuzilishi, yangilash oqimi
  • Vaqt chegaralari, qayta urinish, idempotentlik kaliti

Bu darsga kirmaydi

  • Tokenni qurilmada xavfsiz saqlash va sertifikat pinning: A12-darsda
  • HTTP, TLS, DNS ning ichki ishi: backend yo'l xaritasidagi Tarmoq yo'nalishida
  • WebSocket va gRPC

1. Og'riqQo'lda HTTP

Android'da tarmoqqa birinchi yo'l HttpURLConnection edi: ulanishni ochish, sarlavhalarni qo'yish, oqimdan baytlarni o'qish, ularni satrga, satrni JSONObject ga aylantirib, maydonlarni birma-bir olish. Har bir so'rov o'nlab qator, har bir maydon nomi qo'lda yozilgan satr, va server maydonni o'zgartirsa, xato faqat ish paytida chiqadi. Ulanishlarni qayta ishlatish, kesh, qayta urinish, gzip yo'q edi yoki qo'lda edi. Bunga 4-darsdagi kodirovka tuzoqlari (javob qaysi kodirovkada?) va 5-darsdagi tarmoq kechikishi qo'shiladi.

Bank ilovasi uchun yana ikki og'riq: har bir so'rovga token qo'shish va token muddati tugaganda uni yangilab, so'rovni takrorlash. Agar buni har bir so'rov joyida yozsak, kod takrorlanadi va bir vaqtda bir nechta so'rov tokenni bir necha marta yangilaydi.

2. IchkaridaSo'rovning yo'li

Retrofit va OkHttp

Retrofit'da API interfeys sifatida e'lon qilinadi:

interface CardApi {
    @GET("cards")                 suspend fun cards(): List<CardDto>
    @GET("cards/{id}")            suspend fun card(@Path("id") id: String): CardDto
    @POST("transfers")            suspend fun transfer(@Body body: TransferDto,
                                                        @Header("Idempotency-Key") key: String): TransferResultDto
}

retrofit.create(CardApi::class.java) interfeysni amalga oshiradigan obyektni ish paytida yaratadi (Java'ning dinamik proksi mexanizmi bilan). Metod chaqirilganda Retrofit annotatsiyalarni o'qib, HTTP so'rovni yig'adi, uni OkHttp'ga beradi, javobni konvertor (JSON kutubxonasi) bilan obyektga aylantiradi. suspend metodlar Retrofit 2.6 (2019) dan beri: chaqiruv coroutine'ni to'xtatadi va main-safe.

OkHttp haqiqiy ishni qiladi: ulanishlar havzasi (bitta serverga ulanishni qayta ishlatish), HTTP/2, gzip, kesh, TLS. Uning asosiy kengaytma nuqtasi interceptor: so'rov va javob o'tadigan zanjirning bo'g'ini. Har bir interceptor so'rovni o'zgartirib, keyingisiga beradi va qaytgan javobni o'zgartira oladi. Odatiy zanjir: avtorizatsiya sarlavhasini qo'shuvchi, til va qurilma sarlavhalari, log yozuvchi. Alohida, Authenticator javob 401 bo'lganda chaqiriladi: tokenni yangilab, so'rovni yangi token bilan qaytaradi.

Tokenlar va bir vaqtdagi yangilash

Odatiy sxema ikki token: access token qisqa muddatli (daqiqalar), har bir so'rovga Authorization: Bearer ... sarlavhasida qo'shiladi; refresh token uzoqroq, faqat yangi access token olish uchun ishlatiladi. Access token o'g'irlansa, u tez eskiradi; refresh token esa qurilmada xavfsiz saqlanadi (A12).

Ko'p tokenlar JWT formatida: nuqta bilan ajratilgan uch qism, sarlavha, ma'lumot va imzo, har biri base64url bilan kodlangan. Muhim: JWT shifrlanmagan, faqat imzolangan. Uning ichidagi ma'lumotni (foydalanuvchi ID, muddat) har kim o'qiy oladi; imzo faqat o'zgartirilmaganini kafolatlaydi. Shuning uchun JWT ichiga maxfiy narsa qo'yilmaydi.

Eng nozik joy: ekran ochilganda bir vaqtda beshta so'rov ketdi va hammasi 401 oldi. Har biri o'zicha tokenni yangilasa, serverga beshta yangilash so'rovi ketadi; ko'p serverlarda refresh token bir martalik, va ikkinchi yangilash birinchisining tokenini bekor qiladi: foydalanuvchi tizimdan chiqarib yuboriladi. To'g'ri yechim: yangilashni bitta qulf (Mutex yoki synchronized) ostida bajarish. Birinchi so'rov yangilaydi, qolganlari kutadi va qulfga kirganda token allaqachon yangi ekanini ko'rib (eski token bilan solishtirib), yangilamasdan takrorlaydi. Yuqoridagi chizmada «5 ta parallel 401» holatini ko'ring.

Ktor client

Ktor client Kotlin uchun noldan yozilgan va Multiplatform: bitta tarmoq kodi Android, iOS va desktop'da ishlaydi. Interfeys va annotatsiyalar o'rniga Kotlin funksiyalari: client.get("cards").body<List<CardDto>>(). Ichkarida dvigatel (engine) haqiqiy tarmoq ishini qiladi: Android'da odatda OkHttp yoki CIO. Imkoniyatlar plaginlar bilan qo'shiladi: ContentNegotiation (JSON), Auth (bearer tokenlar, refreshTokens { } bilan yangilash, bir vaqtdagi yangilashni o'zi boshqaradi), HttpTimeout, Logging, HttpRequestRetry.

JSON: qaysi kutubxona

  • kotlinx.serialization: JetBrains'ning kompilyator plagini. @Serializable klasslar uchun serializatorni kompilyatsiyada yaratadi, refleksiyasiz, Multiplatform. Kotlin'ning null bo'lmaydigan turlari va standart qiymatlarini hurmat qiladi: maydon kelmasa va standart qiymati bo'lmasa, aniq xato beradi. Sozlamalar: Json { ignoreUnknownKeys = true; explicitNulls = false }.
  • Moshi: Square'ning kutubxonasi, Kotlin uchun kod yaratish (KSP) rejimi bor, Kotlin turlarini ham tushunadi.
  • Gson: eng eski va keng tarqalgan, lekin refleksiya bilan ishlaydi va Kotlin konstruktorini chetlab o'tadi: kelmagan maydon String turida bo'lsa ham null bo'lib qoladi va standart qiymatlar ishlamaydi (A1-darsdagi tuzoq). Yangi Kotlin loyihalarda tavsiya etilmaydi.

Serverdan kelgan noma'lum maydonlar uchun ignoreUnknownKeys muhim: server yangi maydon qo'shsa, eski ilova versiyalari qulamasligi kerak. Summa uchun serverdan butun son (tiyinda) yoki satr kelishi kerak, double emas (P0, 3-dars).

Xatolar: turlash va ekranga yetkazish

Tarmoq so'rovida beshta xil xato bo'ladi va ularning har biri foydalanuvchiga boshqacha ko'rsatiladi:

Repozitoriy texnik istisnolarni (IOException, HttpException) ushlab, domain'ning o'z xato turiga aylantiradi: sealed interface BankError { NoInternet; Timeout; Unauthorized; Server(code); Business(code, message) }. ViewModel va ekran Retrofit'ni bilmaydi (A5), faqat shu turlarni. Natija Result<T> yoki o'zimizning sealed turimiz bilan qaytariladi. Unutmang: CancellationException qayta tashlanadi (A3).

Vaqt chegaralari, qayta urinish va idempotentlik

  • Vaqt chegaralari: OkHttp'da ulanish, o'qish, yozish va umumiy chaqiruv uchun alohida. Sukut bo'yicha 10 sekund; mobil tarmoqda ba'zi so'rovlar (hisobot yuklash) uchun ko'proq kerak.
  • Qayta urinish: o'qish so'rovlarini (GET) tarmoq xatosida qayta urinish xavfsiz. Pul o'tkazmasi (POST) esa yo'q: javob kelmagani so'rov bajarilmaganini bildirmaydi. Server so'rovni bajargan, javob yo'lda yo'qolgan bo'lishi mumkin, va qayta urinish ikkinchi o'tkazma bo'ladi.
  • Idempotentlik kaliti: ilova har bir to'lov uchun noyob ID yaratadi va uni Idempotency-Key sarlavhasida yuboradi. Server bir xil kalitli takroriy so'rovni bajarmaydi, avvalgi natijani qaytaradi. Shunda qayta urinish xavfsiz. Bu sizning backend tajribangizga ham tegishli: to'lov tizimlari integratsiyasida aynan shunday ishlaydi.

4. Atamalar

REST API
Resurslar (kartalar, o'tkazmalar) va HTTP metodlari (GET, POST, PUT, DELETE) orqali ishlaydigan server interfeysi.
HTTP holat kodi
Javob natijasi: 2xx muvaffaqiyat, 4xx mijoz xatosi (400, 401, 403, 404, 409, 429), 5xx server xatosi.
Retrofit
HTTP API ni annotatsiyali Kotlin/Java interfeysi sifatida e'lon qiladigan kutubxona.
OkHttp
HTTP mijoz: ulanishlar havzasi, HTTP/2, kesh, TLS, interceptorlar.
Interceptor
So'rov va javob o'tadigan zanjir bo'g'ini: sarlavha qo'shish, log, kesh. Application interceptor bitta chaqiruvga bir marta, network interceptor har bir haqiqiy tarmoq so'roviga.
Authenticator
OkHttp'da 401 javobida chaqiriladigan, yangi token bilan so'rov qaytaradigan komponent.
Ktor client
JetBrains'ning Multiplatform HTTP mijozi, dvigatellar va plaginlar bilan.
Serializatsiya
Obyektni JSON ga va JSON ni obyektga aylantirish. kotlinx.serialization, Moshi, Gson.
DTO
Server bilan almashinadigan ma'lumot klassi.
Access token, refresh token
Qisqa muddatli kirish kaliti va uni yangilash uchun uzoq muddatli kalit.
JWT
Sarlavha, ma'lumot va imzodan iborat, base64url bilan kodlangan, imzolangan (shifrlanmagan) token.
Idempotentlik
Amalni bir necha marta bajarish bir marta bajarish bilan bir xil natija berishi. Idempotentlik kaliti bunga erishish usuli.

5. AmaliyotdaTuzoqlar

Tuzoq: log interceptor release'da

HttpLoggingInterceptor BODY darajasida so'rov va javoblarni to'liq logga yozadi: tokenlar, karta raqamlari, balanslar. Release yig'masida qolib ketsa, ular qurilma logida va log yig'uvchi xizmatlarda qoladi.

Log interceptor faqat debug yig'masida qo'shiladi; zarur bo'lsa, maxfiy sarlavhalar redactHeader("Authorization") bilan yashiriladi.

Tuzoq: har bir so'rov tokenni o'zi yangilaydi

Bir vaqtdagi 401 lar parallel yangilashlarni keltirib chiqaradi va refresh token bekor bo'ladi: foydalanuvchi sababsiz tizimdan chiqariladi. Xato faqat sekin internetda va ko'p so'rovli ekranlarda chiqadi, shuning uchun sinovda topilmaydi.

Yangilash bitta joyda (Authenticator yoki Ktor Auth plagini) va qulf ostida, eski tokenni joriysi bilan solishtirib.

Tuzoq: to'lov so'rovini avtomatik qayta yuborish

OkHttp ulanish xatolarida ba'zi so'rovlarni o'zi takrorlaydi (retryOnConnectionFailure), umumiy qayta urinish interceptorlari esa POST ni ham takrorlashi mumkin. Natija: ikki marta yechilgan pul.

Pul bilan bog'liq so'rovlarda idempotentlik kaliti majburiy, va qayta urinish siyosati metod bo'yicha ajratiladi. Javob kelmasa, foydalanuvchiga «holatni tekshiryapmiz» deb, operatsiya holatini alohida so'rov bilan aniqlash.

Qoida: server xatosining tanasini ham o'qing

Bank API lari ko'pincha 200 yoki 4xx bilan birga tanada biznes xatosini qaytaradi: {"code": 1043, "message": "Limit oshib ketdi"}. Faqat HTTP kodiga qarash foydalanuvchiga «Noma'lum xato» ko'rsatadi.

Xato tanasini errorBody() dan o'qib, domain xatosiga aylantirish; matnlarni server tilda berishi yoki ilova o'z tarjimasini ko'rsatishi kelishib olinadi.

6. SuhbatdaSavol va namunaviy javoblar

Retrofit ichkarida qanday ishlaydi?

retrofit.create() Java dinamik proksi bilan interfeysni amalga oshiradi. Metod chaqirilganda annotatsiyalar (bir marta tahlil qilinib keshlanadi) bo'yicha OkHttp Request yig'iladi, Call bajariladi (suspend bo'lsa coroutine to'xtatiladi), javob konvertor orqali obyektga aylantiriladi. Tarmoq ishini OkHttp qiladi: ulanishlar havzasi, interceptor zanjiri, TLS, kesh.

Interceptor va Authenticator farqi? Application va network interceptor farqi?

Interceptor har bir so'rov va javobga ta'sir qiladi (sarlavha, log). Authenticator faqat 401 javobida chaqiriladi va yangi so'rov qaytaradi (yoki null: taslim). Application interceptor bitta chaqiruvga bir marta ishlaydi, qayta yo'naltirish va qayta urinishlarni ko'rmaydi; network interceptor har bir haqiqiy tarmoq almashinuviga, va haqiqiy ulanishni ko'radi.

Token muddati tugaganda nima bo'ladi? Bir vaqtda bir nechta so'rov 401 olsa-chi?

Server 401 qaytaradi, Authenticator refresh token bilan yangi access token oladi, saqlaydi va so'rovni yangi token bilan takrorlaydi. Refresh ham muvaffaqiyatsiz bo'lsa, sessiya tugaydi: tokenlar o'chiriladi va foydalanuvchi kirish ekraniga yuboriladi. Bir vaqtdagi 401 larda yangilash qulf ostida: birinchisi yangilaydi, qolganlari kutadi va token allaqachon yangilanganini ko'rib, yangilamasdan takrorlaydi.

Tarmoq xatolarini qanday qayta ishlaysiz?

Repozitoriyda texnik istisnolarni turlayman: IOException (internet yo'q yoki uzildi), SocketTimeoutException, HttpException kod bo'yicha (401, 403, 404, 409, 429, 5xx), serializatsiya xatosi, va tanadagi biznes xatosi. Ularni domain'ning sealed xato turiga aylantirib, Result bilan qaytaraman. ViewModel holatga xatoni qo'yadi, ekran turga qarab xabar va «qayta urinish» tugmasini ko'rsatadi. CancellationException qayta tashlanadi.

Gson, Moshi va kotlinx.serialization farqi?

Gson refleksiya bilan ishlaydi va Kotlin konstruktorini chetlab o'tadi: null bo'lmaydigan maydonga null tushishi va standart qiymatlar ishlamasligi mumkin. Moshi Kotlin uchun kod yaratish rejimiga ega. kotlinx.serialization kompilyator plagini bilan serializatorlarni kompilyatsiyada yaratadi, refleksiyasiz, Multiplatform, Kotlin turlarini to'liq hurmat qiladi. Yangi loyihada kotlinx.serialization.

Retrofit va Ktor farqi? Qachon qaysi biri?

Retrofit annotatsiyali interfeys, OkHttp ustida, JVM/Android uchun, eng keng tarqalgan, interceptor va Authenticator bilan kengaytiriladi. Ktor Kotlin DSL, Multiplatform, dvigatellar va plaginlar (Auth plagini token yangilashni o'zi boshqaradi). Faqat Android bo'lsa ikkalasi ham yaxshi; iOS bilan umumiy kod kerak bo'lsa Ktor.

JWT nima? Uning ichida parol saqlash mumkinmi?

Uch qism: sarlavha (algoritm), ma'lumot (foydalanuvchi, muddat, ruxsatlar), imzo; base64url bilan kodlangan va nuqta bilan ajratilgan. U imzolangan, shifrlanmagan: ichini har kim o'qiy oladi, lekin o'zgartirsa imzo buziladi. Shuning uchun ichida maxfiy ma'lumot yo'q. Mijoz tomonda muddatni o'qib, so'rovdan oldin yangilash mumkin, lekin tekshiruvni server qiladi.

Nega to'lov so'rovini avtomatik qayta yuborib bo'lmaydi?

Javob kelmagani so'rov bajarilmaganini bildirmaydi: server bajargan bo'lishi mumkin. Qayta yuborish ikkinchi to'lov. Yechim: idempotentlik kaliti sarlavhasi va server tomonda takroriy kalitni aniqlash, yoki operatsiya holatini alohida tekshirish.

7. Tekshiruv

  1. O'tkazma so'rovi interceptorlardan qanday o'tadi? Qaysi interceptorlar bo'lishi kerak?
  2. Ekran ochilganda beshta so'rov 401 oldi. Yangilash kodingiz nima qiladi?
  3. Server javobiga yangi maydon qo'shdi va eski ilova versiyalari qulay boshladi. Sababi va yechimi?
  4. Foydalanuvchi o'tkazma tugmasini bosdi, javob kelmadi (timeout). Ekranda nima ko'rsatasiz va keyin nima qilasiz?
  5. Alipay integratsiyasidagi OAuth token oqimi va mobil ilovadagi token oqimining o'xshash va farqli tomonlari?

Chuqurroq

HTTP kesh va ETag

OkHttp diskdagi kesh bilan server Cache-Control va ETag sarlavhalariga amal qiladi: o'zgarmagan ma'lumot uchun server 304 qaytaradi va tana yuborilmaydi. Bank ilovasida shaxsiy ma'lumot odatda keshlanmaydi, lekin ma'lumotnomalar (valyutalar ro'yxati, filiallar) uchun foydali.
