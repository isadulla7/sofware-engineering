Yo'l xaritasi / Oracle PL/SQL

P3. PL/SQL asoslari: blok, o'zgaruvchilar, %TYPE va %ROWTYPE, kursorlar, exceptionlar

Savol: SQL bor ekan, nega Oracle'ga yana bir til kerak bo'ldi? PL/SQL bloki qanday tuzilgan, kursor ichkarida nima, va xato yuz berganda boshqaruv qayerga ketadi?

Bu nima

PL/SQL (Procedural Language extensions to SQL) Oracle'ning ichiga o'rnatilgan dasturlash tili. Unda o'zgaruvchi, shart, sikl, xatolarni ushlash bor, va SQL buyruqlari kodning ichida to'g'ridan-to'g'ri yoziladi.

O'xshatish: SQL bu omborchiga beriladigan bitta buyurtma («shu tovarlarni olib kel»). PL/SQL esa omborning ichida ishlaydigan menejer: u ko'p buyurtmani ketma-ket beradi, natijaga qarab qaror qiladi va xato bo'lsa nima qilishni biladi. Va eng muhimi: u ombor ichida, telefon orqali emas.

Qayerda ishlatiladi

  • Bank yadro tizimlarida asosiy til: to'lov o'tkazish, foiz hisoblash, kun yopish, hisobotlar. iABS kabi tizimlarda biznes mantiqning katta qismi PL/SQL paketlarida.
  • Integratsiya: Java ilova bitta protsedurani chaqiradi, ichida o'nlab SQL bajariladi.
  • Suhbatda: «kursor turlari», «NO_DATA_FOUND qachon chiqadi», «RAISE_APPLICATION_ERROR», «WHEN OTHERS THEN NULL nega yomon» deyarli har doim so'raladi.

Bu darsning maqsadi

  • PL/SQL qaysi muammo uchun yaratilgan: tarmoq va ikki dvigatel;
  • blok tuzilishi, o'zgaruvchilar, tiplar, %TYPE, %ROWTYPE, yozuvlar;
  • SELECT INTO va uning ikki xatosi;
  • yashirin va oshkor kursorlar, atributlar, kursorli FOR sikl, SYS_REFCURSOR;
  • exception turlari, tarqalishi, RAISE_APPLICATION_ERROR, PRAGMA EXCEPTION_INIT, xatoni loglash.

Bu dars qamraydi

  • Nega PL/SQL kerak: tarmoq aylanishlari va SQL ning protsedur imkoniyati yo'qligi
  • PL/SQL dvigateli va SQL dvigateli, kontekst almashinuvi
  • Blok: DECLARE, BEGIN, EXCEPTION, END; anonim va nomlangan blok
  • Tiplar, %TYPE, %ROWTYPE, RECORD, SUBTYPE, PLS_INTEGER, BOOLEAN
  • Shart va sikllar: IF, CASE, LOOP, WHILE, FOR, EXIT WHEN, CONTINUE
  • Kursorlar: yashirin, oshkor, parametrli, FOR sikl, REF CURSOR, FOR UPDATE va WHERE CURRENT OF
  • Exceptionlar: oldindan aniqlangan, o'zingizniki, tarqalish, loglash

Bu darsga kirmaydi

  • Protsedura, funksiya, paket, trigger: P4-darsda
  • Kolleksiyalar, BULK COLLECT, FORALL, dinamik SQL: P5-darsda
  • Avtonom tranzaksiya va qulflar ichkaridan: P8-darsda (bu yerda faqat loglash uchun eslatiladi)

1. Og'riqHar bir SQL alohida safar

1980-yillarda dastur (masalan, C yoki COBOL'da yozilgan bank operatori ekrani) bazaga har bir SQL buyrug'ini tarmoq orqali alohida yuborardi. Bitta to'lov o'tkazish uchun: to'lovchi hisobini o'qish, qoldiqni tekshirish, debet qilish, kreditlash, provodka yozish, jurnalga yozish. Olti buyruq, olti marta tarmoq orqali borib-kelish.

  • Tarmoq sekin. Har bir borib-kelish millisekundlar oladi, va buyruqning o'zi esa mikrosekundlar. Kun yopishda millionlab buyruq: soatlar faqat kutishga ketadi.
  • SQL da «agar» yo'q. SQL bitta buyruq: «qoldiq yetarli bo'lsa debet qil, aks holda xato qaytar» degan mantiqni SQL ning o'zi yozolmaydi. Bu mantiq har bir ilovada (ekran, batch, shlyuz) qayta yozilardi va bir-biridan farq qilib qolardi.
  • Xavfsizlik. Ilova jadvalga to'g'ridan-to'g'ri yozish huquqiga ega bo'lishi kerak edi. «Faqat to'lov qoidasiga mos yozishga ruxsat ber» deb bo'lmasdi.

Kerak bo'lgan narsa: mantiqni ma'lumotning yoniga, bazaning ichiga ko'chirish. Bitta chaqiruv bilan butun ishni bajaradigan, SQL bilan bir xil tiplarda gapiradigan til. Oracle 1988-yilda PL/SQL ni chiqardi. Uning sintaksisi Ada tilidan olingan: bloklar, kuchli tiplar, exceptionlar, paketlar. Ada AQSh Mudofaa vazirligi uchun ishonchli tizimlar tili sifatida yaratilgan edi.

2. IchkaridaPL/SQL qanday ishlaydi

Ikki dvigatel va tarmoq

Oracle serverining ichida ikkita alohida «dvigatel» bor. PL/SQL dvigateli protsedur kodni bajaradi: o'zgaruvchi, IF, sikl. SQL dvigateli SQL buyruqlarini bajaradi: jadvaldan o'qish, yozish. PL/SQL kodida SQL uchrasa, PL/SQL dvigateli uni SQL dvigateliga uzatadi va natijani qaytarib oladi. Bu uzatish kontekst almashinuvi (context switch) deyiladi: arzon, lekin bepul emas. Pastdagi chizmada bitta to'lovni o'tkazishning uch usuli. Variantni tanlang.

Blok: PL/SQL ning g'ishti

Har qanday PL/SQL kod blokdan iborat. Blok to'rt qismli, ikkitasi ixtiyoriy:

DECLARE                                   -- ixtiyoriy: o'zgaruvchilar, kursorlar, tiplar
  v_qoldiq   hisoblar.qoldiq%TYPE;        -- tip jadval ustunidan olinadi
  v_hisob    hisoblar%ROWTYPE;            -- butun qator tuzilishi
  c_limit    CONSTANT NUMBER := 1000000;  -- o'zgarmas
BEGIN                                     -- majburiy: bajariladigan kod
  SELECT * INTO v_hisob FROM hisoblar WHERE raqam = '20208000100000000001';
  IF v_hisob.qoldiq > c_limit THEN
    DBMS_OUTPUT.PUT_LINE('Katta qoldiq: ' || v_hisob.qoldiq);
  END IF;
EXCEPTION                                 -- ixtiyoriy: xatolarni ushlash
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('Hisob topilmadi');
END;                                      -- majburiy
/
  • Anonim blok: nomsiz, bazada saqlanmaydi, yuborilganda kompilyatsiya qilinib bajariladi. Skriptlar, bir martalik tuzatishlar, Java'dan yuboriladigan qisqa bloklar.
  • Nomlangan blok: protsedura, funksiya, paket, trigger. Bazada kompilyatsiya qilingan holda saqlanadi (P4).
  • Bloklar ichma-ich yozilishi mumkin. Ichki blokda e'lon qilingan o'zgaruvchi faqat shu blokda ko'rinadi. Ichki blokning o'z EXCEPTION qismi bo'lishi mumkin: xatoni joyida ushlab, tashqi kod davom etadi.
  • SQL*Plus va SQL Developer'dagi / belgisi PL/SQL emas: u «blok tugadi, yubor» degan mijoz buyrug'i.

O'zgaruvchilar va tiplar

PL/SQL kuchli tiplangan: har o'zgaruvchining turi e'lon qilinadi. Ko'p tiplar SQL bilan bir xil (NUMBER, VARCHAR2, DATE, TIMESTAMP, CLOB), bir nechtasi faqat PL/SQL da:

  • BOOLEAN: TRUE, FALSE, NULL. 23ai gacha SQL da bunday tur yo'q edi, shuning uchun BOOLEAN qaytaradigan funksiyani SELECT da ishlatib bo'lmasdi.
  • PLS_INTEGER (va uning eski nomi BINARY_INTEGER): 32 bitli butun son, protsessorning o'z arifmetikasi bilan ishlaydi, shuning uchun NUMBER dan tez. Sikl hisoblagichlari va indekslar uchun. Oshib ketsa xato beradi. SIMPLE_INTEGER (11g) null bo'la olmaydi va oshib ketishni tekshirmaydi: yanada tez.
  • NUMBER o'nlik son: 38 xonagacha aniq. Pul hisobida BINARY_DOUBLE emas, doim NUMBER: 0.1 + 0.2 aniq 0.3 bo'lishi kerak (Poydevor P0 ning 3-darsi).
  • VARCHAR2(n): PL/SQL o'zgaruvchisida 32767 baytgacha, jadval ustunida 4000 (yoki EXTENDED rejimda 32767). Jadvaldan 4000 dan uzun matn kelsa CLOB.

E'lon qilingan, lekin qiymat berilmagan o'zgaruvchi NULL. NOT NULL bilan e'lon qilinsa, boshlang'ich qiymat majburiy. P1 dagi uch qiymatli mantiq PL/SQL da ham ishlaydi: IF v_x = NULL hech qachon bajarilmaydi, IF NOT (v_x > 0) esa v_x NULL bo'lsa ham bajarilmaydi.

%TYPE va %ROWTYPE eng foydali «yorliq»lardan. v_qoldiq hisoblar.qoldiq%TYPE «hisoblar jadvalining qoldiq ustuni qanday tipda bo'lsa, shunday» degani. Ertaga ustun NUMBER(18,2) dan NUMBER(20,2) ga kengaytirilsa, kod o'zgarmaydi: qayta kompilyatsiya yetarli, Oracle buni o'zi qiladi. %ROWTYPE butun qator tuzilishini oladi: jadval, view yoki kursor qatori. Uning maydonlariga nuqta bilan murojaat: v_hisob.qoldiq.

O'z tuzilishingiz kerak bo'lsa: TYPE t_natija IS RECORD (summa NUMBER, holat VARCHAR2(10)). Mavjud tipga cheklov qo'shib yangi nom: SUBTYPE t_summa IS NUMBER(20,2).

Shart va sikllar

IF v_qoldiq < v_summa THEN ... ELSIF v_holat = 'BLOK' THEN ... ELSE ... END IF;   -- ELSIF, ELSEIF emas

CASE v_valyuta WHEN 'UZS' THEN v_k := 1; WHEN 'USD' THEN v_k := v_kurs; ELSE RAISE e_valyuta; END CASE;

LOOP  v_i := v_i + 1;  EXIT WHEN v_i > 10;  END LOOP;       -- oddiy sikl
WHILE v_qoldiq > 0 LOOP ... END LOOP;                       -- shartli
FOR i IN 1 .. 10 LOOP ... END LOOP;                         -- i e'lon qilinmaydi, PLS_INTEGER
FOR i IN REVERSE 1 .. 10 LOOP  CONTINUE WHEN MOD(i, 2) = 0; ... END LOOP;   -- CONTINUE: 11g dan

PL/SQL dagi CASE buyrug'ida hech bir WHEN mos kelmasa va ELSE yo'q bo'lsa, CASE_NOT_FOUND xatosi chiqadi. SQL dagi CASE ifodasi esa shunday holatda jimgina NULL qaytaradi.

SELECT INTO va uning ikki xatosi

PL/SQL da natijani o'zgaruvchiga olishning eng oddiy yo'li: SELECT qoldiq INTO v_qoldiq FROM hisoblar WHERE raqam = :r. U aynan bitta qator kutadi:

  • Bitta ham qator yo'q: NO_DATA_FOUND (ORA-01403).
  • Bittadan ko'p: TOO_MANY_ROWS (ORA-01422).

Agregat bilan SELECT COUNT(*) INTO yoki SELECT MAX(...) INTO hech qachon NO_DATA_FOUND bermaydi: agregat doim bitta qator qaytaradi (P1). Bu ba'zan ataylab ishlatiladi, lekin MAX NULL qaytarishini unutmaslik kerak. Mavjudligini tekshirish uchun COUNT(*) qilib butun jadvalni sanash yomon odat: WHERE ... AND ROWNUM = 1 yoki EXISTS bilan birinchi qatorda to'xtash kerak.

Kursor: natija ustidagi ko'rsatkich

Kursor bu Oracle xotirasidagi bajarilgan so'rov va uning natijasi ustida turgan ko'rsatkich. O'xshatish: kitobxonadagi uzun ro'yxat va barmog'ingiz. Ro'yxatni ochasiz (OPEN), barmoq bilan qatorma-qator yurasiz (FETCH), oxiriga yetganingizni bilasiz (%NOTFOUND) va yopasiz (CLOSE). Har qanday SQL, hatto oddiy UPDATE ham, ichkarida kursor orqali bajariladi.

  • Yashirin kursor (implicit): SELECT INTO, INSERT, UPDATE, DELETE, MERGE uchun Oracle o'zi ochadi va yopadi. Natijasini oxirgi buyruqdan keyin SQL%ROWCOUNT, SQL%FOUND, SQL%NOTFOUND bilan bilasiz: «UPDATE nechta qatorni o'zgartirdi?»
  • Oshkor kursor (explicit): CURSOR c IS SELECT ... deb e'lon qilasiz va o'zingiz boshqarasiz. Ko'p qatorli natijani qatorma-qator qayta ishlash uchun.
  • Kursorli FOR sikl: FOR r IN c LOOP ... END LOOP yoki FOR r IN (SELECT ...) LOOP. Ochish, o'qish, oxirni tekshirish va yopishni Oracle o'zi qiladi, xato bo'lsa ham yopadi. 10g dan ichkarida 100 qatordan to'plab o'qiydi (P5), shuning uchun eng ko'p tavsiya qilinadigan shakl.
  • Parametrli kursor: CURSOR c (p_filial VARCHAR2) IS SELECT ... WHERE filial = p_filial, ochishda OPEN c('00450').
  • REF CURSOR va SYS_REFCURSOR: kursorga «havola» o'zgaruvchisi. So'rov ish paytida tanlanadi va eng muhimi, uni protseduradan Java'ga qaytarib, natijani ilovada o'qish mumkin (P11).

Pastdagi chizmada oshkor kursorning hayoti. Tugmalarni ketma-ket bosing va atributlar qanday o'zgarishini kuzating.

Ikki muhim fakt. Birinchisi: natija OPEN paytida aniqlanadi. OPEN dan keyin boshqa sessiya jadvalni o'zgartirib COMMIT qilsa ham, kursor eski holatni ko'radi: Oracle undo ma'lumotidan o'sha paytdagi holatni tiklab beradi (o'qish izchilligi, P8). Ikkinchisi: oshkor kursorni yopmaslik sessiyadagi ochiq kursorlar sonini oshiradi va oxiri ORA-01000: maximum open cursors exceeded. FOR sikl bu xavfdan xoli.

FOR UPDATE va WHERE CURRENT OF. CURSOR c IS SELECT ... FOR UPDATE ochilganda tanlangan hamma qatorlarni qulflaydi, shuning uchun ularni o'qib, keyin yangilash orasida hech kim o'zgartira olmaydi. Sikl ichida UPDATE hisoblar SET ... WHERE CURRENT OF c joriy qatorni ROWID bo'yicha yangilaydi. Qulflar COMMIT da bo'shaydi, va COMMIT dan keyin bunday kursordan o'qish ORA-01002: fetch out of sequence beradi.

Exception: xato bo'lganda boshqaruv qayerga ketadi

Exception bu bajarilish paytida yuz bergan xato yoki ataylab ko'tarilgan holat. Xato chiqqan zahoti joriy blokning qolgan kodi bajarilmaydi, va boshqaruv shu blokning EXCEPTION qismiga o'tadi. U yerda mos WHEN bo'lsa, ushlanadi va blokdan keyingi kod davom etadi. Bo'lmasa, xato tashqi blokka «ko'tariladi» (propagation), va hech kim ushlamasa, chaqirgan ilovaga ORA-xxxxx bo'lib qaytadi. Pastda ichma-ich bloklar. Holatni tanlang.

Exception turlari:

  • Oldindan nomlangan: NO_DATA_FOUND, TOO_MANY_ROWS, DUP_VAL_ON_INDEX (UNIQUE buzildi), ZERO_DIVIDE, VALUE_ERROR (satr sig'madi yoki tip almashmadi), INVALID_NUMBER (SQL ichida satr songa aylanmadi), CURSOR_ALREADY_OPEN, INVALID_CURSOR.
  • Nomsiz Oracle xatolari: minglab ORA- kodlarning ko'pchiligining nomi yo'q. Ularga nom berish: e_band EXCEPTION; PRAGMA EXCEPTION_INIT(e_band, -54); (ORA-00054: resource busy, NOWAIT qulfda).
  • O'zingizniki: e_mablag_yetarli_emas EXCEPTION; va RAISE e_mablag_yetarli_emas;. Faqat PL/SQL ichida ma'noga ega, ilovaga «User-Defined Exception» bo'lib boradi.
  • RAISE_APPLICATION_ERROR(-20001, 'Mablag'' yetarli emas'): ilovaga o'z kod va matningiz bilan xato qaytarish. Kodlar −20000 dan −20999 gacha. Java'da SQLException.getErrorCode() 20001 ni beradi. Uchinchi parametr TRUE bo'lsa, oldingi xatolar steki saqlanadi.

Ushlash ichida foydali vositalar: SQLCODE (xato raqami), SQLERRM (matni), DBMS_UTILITY.FORMAT_ERROR_STACK (to'liq stek), va eng muhimi DBMS_UTILITY.FORMAT_ERROR_BACKTRACE (10g): xato qaysi paketning qaysi qatorida chiqqanini ko'rsatadi. Usiz «qayerdadir NO_DATA_FOUND» degan logdan foyda kam. RAISE; (argumentsiz) ushlangan xatoni qayta ko'taradi: logga yozib, keyin yuqoriga uzatish uchun.

Xato va tranzaksiya. Bitta SQL buyrug'i xato bersa, Oracle faqat shu buyruqning o'zgarishlarini bekor qiladi (statement-level rollback); oldingi muvaffaqiyatli buyruqlar tranzaksiyada qoladi. Anonim blok yoki protsedura ushlanmagan xato bilan tugasa, Oracle chaqiruvdan oldingi holatga qaytaradi (blok darajasida, yashirin savepoint bilan). Xatoni ushlab, hech narsa qilmasangiz, blokning yarim bajarilgan o'zgarishlari tranzaksiyada qoladi va keyingi COMMIT ularni saqlaydi. Bu P8 darsida chuqurroq.

Loglash. Xatoni jadvalga yozib, keyin xatoni qaytarsangiz, ilova ROLLBACK qiladi va log yozuvi ham yo'qoladi. Shuning uchun log protsedurasi PRAGMA AUTONOMOUS_TRANSACTION bilan yoziladi: u o'z alohida tranzaksiyasida COMMIT qiladi va asosiy tranzaksiyaga ta'sir qilmaydi (P8).

3. Yaratilishi va o'zgarishiPL/SQL tarixi

4. Atamalar

PL/SQL
Oracle'ning SQL ga protsedur qo'shimchasi: blok, o'zgaruvchi, shart, sikl, exception, paket. Ada tili asosida.
PL/SQL dvigateli, SQL dvigateli
Serverdagi ikki bajaruvchi: protsedur kodni va SQL buyruqlarini bajaradi.
Kontekst almashinuvi
PL/SQL dan SQL ga va qaytib o'tish. Siklda har qator uchun bo'lsa, sezilarli narx. Yechimi P5 da: BULK.
Tarmoq aylanishi (round trip)
Ilovadan bazaga so'rov yuborib, javob olish. Ko'pincha buyruqning o'zidan qimmat.
Blok: DECLARE, BEGIN, EXCEPTION, END
E'lonlar, kod, xatolarni ushlash, tugash. Anonim blok saqlanmaydi, nomlangani bazada saqlanadi.
%TYPE, %ROWTYPE
Ustun tipi va qator tuzilishini jadval, view yoki kursordan olish. Jadval o'zgarsa kod moslashadi.
RECORD, SUBTYPE
O'z maydonlari bo'lgan tuzilma; mavjud tipga yangi nom va cheklov.
PLS_INTEGER, SIMPLE_INTEGER
Tez 32 bitli butun sonlar. Ikkinchisi null bo'lmaydi va oshib ketishni tekshirmaydi.
SELECT INTO
Aynan bitta qatorni o'zgaruvchiga olish. 0 qator: NO_DATA_FOUND, ko'p qator: TOO_MANY_ROWS.
Kursor
Bajarilgan so'rov natijasi ustidagi ko'rsatkich va unga ajratilgan xotira.
Yashirin va oshkor kursor
Oracle o'zi boshqaradigan (DML, SELECT INTO); dasturchi e'lon qilib OPEN, FETCH, CLOSE qiladigan.
%FOUND, %NOTFOUND, %ROWCOUNT, %ISOPEN
Oxirgi FETCH qator berdimi; bermadimi; shu paytgacha nechta qator olindi; kursor ochiqmi. Yashirin kursor uchun SQL%... ko'rinishida.
Kursorli FOR sikl
OPEN, FETCH, EXIT va CLOSE ni avtomatik qiladigan sikl. 10g dan ichkarida 100 talab o'qiydi.
REF CURSOR, SYS_REFCURSOR
Kursorga havola o'zgaruvchisi. So'rov ish paytida tanlanadi, ilovaga qaytariladi.
FOR UPDATE, WHERE CURRENT OF
Kursor qatorlarini ochishda qulflash; joriy kursor qatorini yangilash.
Exception
Bajarilishni to'xtatib, EXCEPTION qismiga o'tkazadigan xato yoki holat.
Tarqalish (propagation)
Ushlanmagan exception tashqi blokka, keyin chaqiruvchiga ko'tarilishi.
RAISE, RAISE_APPLICATION_ERROR
Exception ko'tarish; ilovaga −20000...−20999 kodli o'z xatoingizni qaytarish.
PRAGMA EXCEPTION_INIT
Nomsiz ORA- xatosiga nom berish, uni WHEN da ushlash uchun.
SQLCODE, SQLERRM, FORMAT_ERROR_BACKTRACE
Xato raqami, matni, va xato chiqqan qator raqamlari bilan stek.
Statement-level rollback
Xato bergan SQL buyrug'ining faqat o'z o'zgarishlari bekor qilinadi, tranzaksiya davom etadi.

5. AmaliyotdaTuzoqlar

Tuzoq: WHEN OTHERS THEN NULL

Xato yutib yuboriladi: na log, na xabar. To'lov protsedurasining yarmi bajarilgan, yarmi yo'q, chaqiruvchi esa «muvaffaqiyat» deb o'ylaydi. Keyin «pul yechildi, lekin kelmadi» degan shikoyat va hech qanday iz yo'q. Oracle 11g dan bunday kod uchun kompilyator ogohlantirishi bor: PLW-06009.

To'g'risi: faqat kutilgan aniq xatolarni ushlash (WHEN NO_DATA_FOUND). WHEN OTHERS faqat eng tashqi darajada, logga yozish va RAISE; bilan qayta ko'tarish uchun.

Tuzoq: mavjudligini COUNT(*) bilan tekshirish

SELECT COUNT(*) INTO v_n FROM tolovlar WHERE mijoz_id = :id; IF v_n > 0 THEN .... Mijozning 2 million to'lovi bo'lsa, hammasi sanaladi, javob esa «bor» yoki «yo'q» xolos. Va tekshiruv bilan keyingi amal orasida boshqa sessiya ma'lumotni o'zgartirishi mumkin.

To'g'risi: SELECT COUNT(*) INTO v_n FROM dual WHERE EXISTS (SELECT 1 FROM tolovlar WHERE ...) yoki ... AND ROWNUM = 1. Undan ham yaxshisi: tekshirmasdan amalni bajarib, natijani SQL%ROWCOUNT yoki exception bilan bilish.

Tuzoq: SQL%ROWCOUNT ni kech o'qish

UPDATE ...; log_yoz(...); IF SQL%ROWCOUNT = 0 THEN. SQL% atributlari oxirgi bajarilgan SQL ga tegishli. log_yoz ichida INSERT bor edi, shuning uchun SQL%ROWCOUNT endi uning natijasi: 1.

To'g'risi: SQL%ROWCOUNT ni DML dan darhol keyin o'zgaruvchiga saqlash.

Tuzoq: siklda qatorma-qator ishlash (row by row, «slow by slow»)

FOR r IN (SELECT ... 1 million qator) LOOP UPDATE ... WHERE id = r.id; END LOOP;. Har qator uchun ikki kontekst almashinuvi va alohida UPDATE. Bitta UPDATE ... WHERE ... buni bir necha marta tezroq qiladi.

To'g'risi, Tom Kyte qoidasi: iloji bo'lsa bitta SQL; bo'lmasa PL/SQL da to'plam bilan (BULK COLLECT va FORALL, P5); faqat undan keyin qatorma-qator.

Tuzoq: COMMIT ni sikl ichida qilish

«Undo to'lib qolmasin» deb har 1000 qatorda COMMIT. Bu sekinlashtiradi (har COMMIT redo'ni diskka yozishni kutadi), yarim yo'lda yiqilsa ma'lumot yarim yangilangan holda qoladi va qayta ishga tushirish murakkab. O'qiyotgan kursorning o'zi esa ORA-01555: snapshot too old olishi mumkin.

To'g'risi: tranzaksiya chegarasi biznes ma'nosi bo'yicha (bitta to'lov, bitta hujjat paketi), va jarayon qayta ishga tushirilsa davom eta oladigan qilib yozish. P8 da batafsil.

Tuzoq: tipni qattiq yozish

v_raqam VARCHAR2(20). Bir yil o'tib hisob raqami ustuni 27 belgiga kengaytirildi va kod ORA-06502: numeric or value error: character string buffer too small bilan yiqila boshladi.

To'g'risi: v_raqam hisoblar.raqam%TYPE. Paket spetsifikatsiyasida esa umumiy SUBTYPE lar.

6. SuhbatdaSavol va namunaviy javoblar

Avval javobni o'zingiz ovoz chiqarib ayting, keyin oching. iABS tajribangizdan misol qo'shsangiz, javob kuchliroq eshitiladi.

PL/SQL nima uchun kerak, SQL dan farqi nima?

SQL deklarativ va bitta buyruq: shart, sikl, o'zgaruvchi, xatolarni ushlash yo'q. PL/SQL Oracle ichidagi protsedur til: SQL ni o'z ichiga oladi va unga mantiq qo'shadi. Asosiy foydalari: biznes mantiq ma'lumot yonida, bitta chaqiruv bilan ko'p SQL bajariladi, ya'ni tarmoq aylanishlari kam; hamma ilova bir xil qoidani chaqiradi; huquq jadvalga emas, protseduraga beriladi; kod kompilyatsiya qilingan holda saqlanadi va bog'liqliklar kuzatiladi. Narxi: kod bazaga bog'lanadi, va PL/SQL bilan SQL orasida kontekst almashinuvi bor.

PL/SQL bloki qanday tuzilgan? Anonim blok va protsedura farqi?

DECLARE (ixtiyoriy), BEGIN (majburiy), EXCEPTION (ixtiyoriy), END. Anonim blok nomsiz, saqlanmaydi, har yuborilganda kompilyatsiya qilinadi (shared pool'da keshlanishi mumkin). Protsedura nomlangan, bazada kompilyatsiya qilingan holda saqlanadi, parametr oladi, huquq beriladi, boshqa koddan chaqiriladi, va unga bog'liq obyektlar kuzatiladi. Bloklar ichma-ich bo'ladi, ichki blokning o'z exception qismi bo'lishi mumkin.

%TYPE va %ROWTYPE nima va nega ularni ishlatish kerak?

%TYPE o'zgaruvchi tipini jadval ustuni yoki boshqa o'zgaruvchidan oladi, %ROWTYPE esa butun qator tuzilishini jadval, view yoki kursordan. Foydasi: ustun tipi yoki uzunligi o'zgarsa, kod qo'lda o'zgartirilmaydi, Oracle bog'liq obyektni qayta kompilyatsiya qiladi. Xatolar kamayadi (masalan, buffer too small). %ROWTYPE bilan butun qatorni bitta SELECT INTO ga olish va INSERT da VALUES v_qator yozish mumkin.

SELECT INTO qanday xatolar beradi va ularni qanday hal qilasiz?

Qator topilmasa NO_DATA_FOUND, bittadan ko'p bo'lsa TOO_MANY_ROWS. Hal qilish holatga bog'liq: topilmaslik normal bo'lsa, ichki blokda WHEN NO_DATA_FOUND bilan sukut qiymat berish; kalit bo'yicha qidiruvda TOO_MANY_ROWS ma'lumot xatosi, uni yashirmaslik kerak. Agregat bilan SELECT INTO (COUNT, MAX) NO_DATA_FOUND bermaydi. NO_DATA_FOUND ning yana bir o'ziga xosligi: SQL ichidan chaqirilgan funksiyada u ushlanmasa, so'rov xato bermay, NULL qaytaradi.

Kursor nima? Yashirin va oshkor kursor farqi?

Kursor bajarilgan so'rov natijasi ustidagi ko'rsatkich va unga ajratilgan xotira (PGA dagi kontekst va shared pool'dagi umumiy qism). Yashirin kursorni Oracle har bir DML va SELECT INTO uchun o'zi ochadi va yopadi, natijasini SQL%ROWCOUNT, SQL%FOUND bilan bilamiz. Oshkor kursorni CURSOR c IS bilan e'lon qilib OPEN, FETCH, CLOSE qilamiz, ko'p qatorli natija uchun. Atributlari %FOUND, %NOTFOUND, %ROWCOUNT, %ISOPEN. Eng qulay shakli kursorli FOR sikl: ochish, yopish va oxirni tekshirish avtomatik, 10g dan ichkarida to'plab o'qiydi.

Kursor OPEN qilingandan keyin boshqa sessiya ma'lumotni o'zgartirsa, FETCH nimani ko'radi?

OPEN paytidagi holatni. Oracle o'qish izchilligini ta'minlaydi: so'rov boshlangan paytdagi SCN bo'yicha, kerak bo'lsa undo dan bloklarning eski versiyasini tiklaydi. Kursor ochiq turgan vaqtda undo ma'lumoti ustidan yozib yuborilsa, ORA-01555 snapshot too old chiqadi. Shuning uchun juda uzoq ochiq turadigan kursorlar va sikl ichida COMMIT xavfli.

REF CURSOR nima va qachon kerak?

Kursorga havola o'zgaruvchisi: so'rov e'londa emas, OPEN FOR paytida beriladi, shuning uchun dinamik bo'lishi mumkin. Asosiy ishlatilishi: protseduradan natija to'plamini ilovaga qaytarish. Java'da CallableStatement da OracleTypes.CURSOR chiqish parametri sifatida ro'yxatdan o'tkaziladi va ResultSet bo'lib o'qiladi. Kuchli REF CURSOR qaytaradigan tuzilish bilan e'lon qilinadi, kuchsizi (SYS_REFCURSOR) har qanday so'rov uchun. Uni yopish chaqiruvchi tomonning vazifasi.

Exception qanday tarqaladi? Ichki blokda ushlansa nima bo'ladi?

Xato chiqqan zahoti blokning qolgan kodi o'tkazib yuboriladi va shu blokning EXCEPTION qismi tekshiriladi. Mos WHEN bo'lsa, xato ushlanadi va boshqaruv shu blokdan keyingi buyruqqa o'tadi, ya'ni tashqi kod davom etadi. Bo'lmasa, xato tashqi blokka, keyin chaqiruvchi protseduraga, oxiri ilovaga ko'tariladi. DECLARE qismidagi xato (masalan, boshlang'ich qiymat sig'madi) o'sha blokning emas, tashqi blokning EXCEPTION qismida ushlanadi. EXCEPTION qismining ichidagi xato ham tashqariga ketadi.

RAISE va RAISE_APPLICATION_ERROR farqi?

RAISE nomlangan exception ni ko'taradi (o'zingiznikini yoki oldindan aniqlanganini), argumentsiz RAISE esa EXCEPTION qismida ushlangan xatoni qayta ko'taradi. RAISE_APPLICATION_ERROR(-20000...-20999, matn) ilovaga tushunarli kod va xabar bilan xato qaytaradi; Java'da SQLException bo'lib keladi. Biznes xatolari (mablag' yetarli emas, hisob bloklangan) uchun shu ishlatiladi, va kodlar paket konstantalarida yoki jadvalda tartib bilan saqlanadi.

WHEN OTHERS THEN NULL nega yomon? WHEN OTHERS ni qachon ishlatish mumkin?

U har qanday xatoni, kutilmaganini ham, yashiradi: chaqiruvchi muvaffaqiyat deb o'ylaydi, tranzaksiyada yarim bajarilgan o'zgarishlar qoladi, va diagnostika uchun iz yo'q. WHEN OTHERS faqat logga yozish (SQLCODE, SQLERRM, FORMAT_ERROR_BACKTRACE, parametrlar) va keyin RAISE bilan qayta ko'tarish uchun, odatda eng tashqi darajada yoki tizim chegarasida (masalan, navbatdagi xabarni qayta ishlashda: xatoni belgilab, keyingisiga o'tish).

Xatoni loglash uchun nega avtonom tranzaksiya kerak?

Xato ushlanib, logga yozilib, keyin qayta ko'tarilsa, chaqiruvchi ROLLBACK qiladi va log INSERT i ham bekor bo'ladi. PRAGMA AUTONOMOUS_TRANSACTION bilan yozilgan log protsedurasi o'z mustaqil tranzaksiyasida ishlaydi va o'zi COMMIT qiladi: log saqlanadi, asosiy tranzaksiya esa bekor qilinadi. Avtonom tranzaksiyani faqat loglash va audit kabi mustaqil ishlarga ishlatish kerak, biznes ma'lumot uchun emas.

PRAGMA EXCEPTION_INIT nima?

Nomsiz Oracle xato kodiga nom beradi, shunda uni WHEN da aniq ushlash mumkin: e_qulf EXCEPTION; PRAGMA EXCEPTION_INIT(e_qulf, -54); va WHEN e_qulf THEN (SELECT FOR UPDATE NOWAIT band qatorga urilganda). Shuningdek o'z RAISE_APPLICATION_ERROR kodingizga nom berib, uni boshqa paketda ushlash uchun ham ishlatiladi.

PLS_INTEGER va NUMBER farqi?

NUMBER o'nlik, 38 xonagacha aniq, dasturiy arifmetika bilan hisoblanadi. PLS_INTEGER 32 bitli butun son, protsessor arifmetikasi bilan, shuning uchun hisoblagich va indekslarda ancha tez; chegaradan oshsa xato. SIMPLE_INTEGER undan ham tez: NOT NULL va oshib ketish tekshirilmaydi. Pul summalari doim NUMBER, chunki o'nlik aniqlik kerak.

Bitta UPDATE nechta qatorni o'zgartirganini qanday bilasiz?

UPDATE dan darhol keyin SQL%ROWCOUNT. U oxirgi bajarilgan SQL ga tegishli, shuning uchun boshqa SQL dan oldin o'zgaruvchiga saqlash kerak. SQL%NOTFOUND yoki SQL%ROWCOUNT = 0 bo'lsa, masalan, hisob topilmagan yoki holati mos emas: RAISE_APPLICATION_ERROR bilan biznes xatosi qaytariladi. UPDATE qator topmasa, xato bermaydi: buni dasturchi o'zi tekshiradi.

7. Tekshiruv

Javoblarni chatga yozing. Kod yozish savollarida sintaksis ikkinchi darajali, mantiq muhim.

  1. Hisob raqami beriladi. Qoldiqni o'qing; hisob topilmasa 0, hisob bloklangan bo'lsa -20010 kodli xato qaytaradigan anonim blok yozing.
  2. Quyidagining natijasi nima va nega: DECLARE v NUMBER; BEGIN IF v <> 5 THEN DBMS_OUTPUT.PUT_LINE('farqli'); ELSE DBMS_OUTPUT.PUT_LINE('teng'); END IF; END;
  3. Oshkor kursor bilan va kursorli FOR sikl bilan bir xil ishni yozing: filialning ochiq hisoblari bo'yicha qoldiq jami. Qaysi biri yaxshi va nega? Bu ishni PL/SQL siz qanday qilasiz?
  4. Protsedura ichida: UPDATE muvaffaqiyatli, keyin INSERT DUP_VAL_ON_INDEX berdi va ushlanmadi. Chaqirgan Java kodi COMMIT qilsa, UPDATE saqlanadimi?
  5. Ish joyingizdagi kodda WHEN OTHERS qanday ishlatilganini eslang. Qayerda u to'g'ri, qayerda xatoni yashiradi?

Chuqurroq

PL/SQL kompilyatsiyasi: interpretatsiya va native

PL/SQL kodi kompilyatsiyada «m-code» degan oraliq kodga aylanadi va PL/SQL virtual mashinasida bajariladi (Java baytkodiga o'xshash, Poydevor P0 7-dars). 9i dan native kompilyatsiya bor: kod mashina kodiga aylanadi va hisob-kitobga boy kodni tezlashtiradi; SQL ko'p kodda farq sezilmaydi. 10g dan optimallashtiruvchi kompilyator (PLSQL_OPTIMIZE_LEVEL, sukut 2): ba'zi sikllarni o'zi qayta yozadi, masalan kursorli FOR siklni to'plab o'qishga.

DBMS_OUTPUT nega «oxirida» chiqadi

DBMS_OUTPUT.PUT_LINE ekranga yozmaydi: u sessiya xotirasidagi buferga yozadi. SQL*Plus yoki SQL Developer blok tugagandan keyin buferni o'qib, ko'rsatadi. Shuning uchun uzun jarayonning borishini u bilan kuzatib bo'lmaydi: buning uchun DBMS_APPLICATION_INFO.SET_MODULE va SET_ACTION (V$SESSION da ko'rinadi), V$SESSION_LONGOPS yoki avtonom tranzaksiyali log jadvali.

Kompilyator ogohlantirishlari va PL/Scope

ALTER SESSION SET PLSQL_WARNINGS = 'ENABLE:ALL' dan keyin kompilyatsiya ogohlantirishlari: ishlatilmagan o'zgaruvchi, yetib bo'lmaydigan kod, WHEN OTHERS siz RAISE (PLW-06009), yashirin tip almashinuvi. PL/Scope (11g) esa kod ichidagi barcha identifikatorlar va 12c R2 dan SQL buyruqlari haqida ma'lumot yig'adi: «bu ustunni qaysi paketlar o'zgartiradi» degan savolga javob.
